# Feature: frontend-workbench（spec.md）

> Spec 阶段产物：按 **what/why** 写需求，不含技术方案。本文件只描述"要什么行为、如何验收"；
> 一切实现机制（框架用法、构建工具、测试框架、存储方式、文件组织等）在 `plan.md`。
> **Gate 1 记录**：2026-10-27 草案（Clarify 问题见 §5，待 Walter 回答并批准后冻结）。

## 1. 背景与动机（why）

- 产品核心循环的终点是用户每天打开的界面：图表、日报、对话、知识库都在这里呈现（docs/plan.md §2；docs/architecture.md §2 Frontend 层）。
  仓库目前没有任何前端代码，Phase 1 的图表模板库、日报管线、pi 集成都需要一个承载界面才能被用户看见和验收。
- 界面形态与视觉体系已由 D-011 冻结（首页 = 工作台 + 今日焦点带、左侧菜单、模块库 + 固定栅格、底部对话抽屉、
  暗色玻璃、红涨绿跌限行情模块），`docs/designUI.md` 是细则权威；FTEngine 的 UI 规范资产（`D:\FTEngine\design\UI`、
  `design\Graphs\Palette`）是数值与规则的来源，尚未按 designUI §8 移植。
- 本 feature 交付前端的**地基**：设计系统（令牌）、应用外壳（导航/布局/路由）、工作台与模块系统、AI 对话抽屉与
  CoT 时间线的界面形态、图表暗色主题，以及一层与后端隔离的数据访问契约。后续的图表模板、日报、知识库、设置等
  页面都在这层地基上生长。
- 与 data-layer 并行：data-layer 明确不提供"任何面向前端的 HTTP API"（specs/data-layer/spec.md §2 非目标），
  `backend/api` 尚不存在。因此本 feature 全部由可替换的 mock 数据驱动，不依赖任何后端 feature；
  前后端之间唯一的接口是本 feature 定义的数据访问契约（R-007），由后续 `api` feature 实现。

## 2. 目标与非目标

### 目标（what）

- **设计系统**：界面令牌（色、玻璃层级、字体三族、字号阶梯、间距、圆角、层级）单一来源；从 FTEngine UI 规范资产按需移植并做暗色适配；代码只引令牌，不写字面量
- **应用外壳**：加载页 → 工作台；左侧固定菜单（8 项 + 动态扩展区）、顶栏（资讯 ticker + 数据源状态）、内容区路由；侧栏可收起；窄窗口行为
- **工作台**：今日焦点带（固定顶部，承载当日日报核心结论与数字，点击展开完整日报）+ 模块栅格
- **模块系统**：模块库（v1 七个模块）、固定栅格、添加/移除/排序（无拖拽）、布局持久化；统一模块壳（标题/副标/右注/状态徽/AI 角标/空态）
- **AI 对话**：底部固定输入栏 → 向上展开抽屉；CoT 时间线，每步可展开；运行中可切走页面、agent 后台继续；模块角标（运行中/完成）；agent 可引导跳转到模块；事件流契约（mock 回放）
- **图表暗色主题**：由令牌生成图表主题并注册；黛驼体系暗色亮化版；退役色不得出现；至少一张样例图在模块中渲染
- **数据访问契约**：前端所需数据与事件全部经一层类型化契约访问；mock 实现与真实实现可切换；契约文档化，供后端 `api` feature 实现
- **规范资产移植登记**：本 feature 用到的 FTEngine UI 条目搬入 `design/ui/`，保留原条目 id 与"为什么"，并登记暗色适配差异
- **质量守卫**：令牌对拍、字面量扫描、结构契约检查、组件/端到端测试、人工验收清单

### 非目标

- 真实后端对接（网络客户端实现、鉴权、令牌）：归 backend `api` feature；本 feature 只定契约 + mock
- Electron 桌面外壳、托盘、通知、打包（desktop-shell feature）；本 feature 在浏览器中验收
- 图表模板库（14 种 kind、chart-spec 编译、两级浮窗、复制/截图/水印、CK 体检规则）：归 chart-templates feature；本 feature 只做主题与一张样例图
- 日报、价格、平衡表、物流、专题研究、知识库、设置各页的实际内容与功能（各自 feature）；本 feature 只提供路由与占位页
- 七个模块的真实数据与完整交互（各 domain feature）；本 feature 按 Q-001 裁定的深度做 mock 内容
- 亮色纸底主题与导出/打印映射（随日报导出 feature）
- 自由拖拽布局、用户自定义图表属性（v2）
- 多语言、移动端、无障碍专项

## 3. 需求条目

### R-001 设计系统与令牌

- **what**：
  - 界面令牌只有一处权威登记：色彩（背景渐变、玻璃面/边/模糊、文字三级、点睛红、琥珀、涨跌专色、状态色）、字体三族栈、字号阶梯、间距三档、圆角与例外、层级 z。数值来自 designUI.md §2 与 FTEngine UI 条目（Foundations / Colors / Fonts / Layout）的暗色适配版；散文与代码只引令牌名
  - **玻璃层级限三层**：焦点带 / 模块 / 抽屉；不得出现第四层玻璃面
  - **字体三族分工**沿用 FTEngine DNA：衬线用于品牌字标、页标题、模块大标题、KPI 大数；无衬线用于正文、导航、按钮、表格文字；等宽用于一切数值、代码、单位、ticker；数值一律等宽 + 等宽数字对齐 + 右对齐
  - **色语义**：涨跌专色（涨 `#C98A8F` / 跌 `#8FB8A4`）只在行情模块使用、只涂字色不涂底；分析类元素保持"红 = 负/减"；界面点睛红与琥珀（= 非实绩 / 可编辑 / 待更新）的语义沿用 FTEngine Foundations；退役色（朱 / 骐驎 / 群青 / 石绿 / 茈藐）禁用
  - **空与零**：空值铺 en dash；差值带正号；按显示位取整为零的数中性——不着色、不带号、不印负零
  - **双语层级**：中文为主标题，英文以全大写小字号加宽字距作副标伴随（推断沿用 FTEngine，见 Q-008）
- **验收规则**：
  - [ ] AC-001-1 令牌登记与运行时样式对拍：登记的每个令牌在运行时样式/主题中存在且值相等（自动测试）
  - [ ] AC-001-2 代码零未登记色值字面量：静态扫描前端源码（样式与脚本）中的颜色字面量，命中即失败；规则与阳性/阴性样例随实现提交，阳性样例须命中
  - [ ] AC-001-3 玻璃层级 ≤ 3：静态检查只允许三个登记的玻璃层级被引用；整页截图层次清楚（人工验收）
  - [ ] AC-001-4 字族分工与数值规则：组件测试断言 KPI / 标题 / 正文 / 数值元素的字族、等宽数字对齐与右对齐；格式化函数单元测试覆盖 en dash / 正号 / 零中性 / 负零
  - [ ] AC-001-5 涨跌色只出现在行情模块且只涂字色：静态检查涨跌令牌的引用范围限于行情模块；分析类元素引用"红 = 负"令牌（组件测试）
  - [ ] AC-001-6 退役色不出现在令牌、主题与源码（静态扫描）

### R-002 应用外壳与导航

- **what**：
  - **启动**：加载页（可承载加载进度与通知文案）→ 就绪后进入工作台；两者之间无空白闪屏
  - **左侧菜单固定八项与顺序**：工作台 · 日报 · 价格 · 平衡表 · 物流 · 专题研究 · 知识库 · 设置；专题研究下有动态扩展区（随用户新增研究追加子项，v1 由 mock 列表驱动）；当前项有明确指示；除工作台外各页为占位页（空态文案注明归属 feature）
  - **顶栏**：资讯 ticker（滚动的新闻条目）+ 数据源状态（各源新鲜度与待更新点）；两者数据经契约取 mock
  - **侧栏可收起/展开**，状态持久化（刷新后保持）
  - **窄窗口**：窗口窄于登记断点时侧栏塌成顶部横向导航、栅格列数按登记收缩；任何宽度下不出现横向页面滚动条
  - **路由可直达**：每个菜单项有稳定地址；刷新后停留在当前页
- **验收规则**：
  - [ ] AC-002-1 加载页 → 工作台（端到端：加载页出现、就绪后工作台出现，无空白帧）
  - [ ] AC-002-2 菜单八项与顺序、当前项指示、占位页（端到端：逐项点击，地址与当前项一致；刷新保持）
  - [ ] AC-002-3 专题研究动态子项由 mock 列表驱动（契约 mock 增加一项 → 菜单出现该项）
  - [ ] AC-002-4 顶栏 ticker 与数据源状态渲染 mock 数据；状态点语义（新鲜 / 待更新）取令牌（组件测试）
  - [ ] AC-002-5 侧栏收起/展开持久化（端到端：收起 → 刷新 → 仍收起）
  - [ ] AC-002-6 窄窗口断点行为（端到端：在登记断点上下各取一个视口，断言侧栏形态、栅格列数、文档无横向溢出）

### R-003 工作台与今日焦点带

- **what**：
  - 工作台首页 = 顶部今日焦点带 + 模块栅格；焦点带固定（不可移除、不进模块库）
  - 焦点带内容：当日日报的核心结论（若干条）+ 关键数字（含方向与变化量），经契约取 mock；点击展开完整日报（v1：跳转日报占位页并携带当日标识）
  - 焦点带中每个数字在契约里**声明语义**（行情 / 分析），按语义取色：行情用涨跌专色，分析用"红 = 负"；数字遵守 R-001 数值规则
  - 无当日日报时显示空态并说明原因（如"今日日报尚未生成"），不留空白
- **验收规则**：
  - [ ] AC-003-1 焦点带渲染 mock 日报摘要：结论条目、数字、方向色（组件测试）
  - [ ] AC-003-2 点击焦点带跳转日报页并携带当日标识（端到端）
  - [ ] AC-003-3 无日报时显示空态文案（组件测试）
  - [ ] AC-003-4 数字按声明语义取色：行情语义用涨跌色，分析语义用"红 = 负"（组件测试）

### R-004 模块系统

- **what**：
  - **模块库 v1 七个模块**：行情价格、库存/供需指标、物流在途、当前头寸、文档目录、关注列表、数据发布日历；每个模块有唯一 id、名称、说明、默认尺寸档位（栅格跨列数）
  - **固定栅格**：列数由断点登记决定；模块按顺序填入；用户可从模块库添加、从工作台移除、用上下移动调整顺序；不做拖拽（顺序机制见 Q-005）
  - **布局持久化**（启用模块与顺序）；默认布局 = 全部七个模块按登记顺序
  - **统一模块壳**：中文标题 + 英文副标（可选）+ 右注（单位 / 截至时间）+ 状态徽（正常 / 警告 / 异常 / 样例，样例态用不靠颜色的区分）+ AI 角标位 + 加载 / 空 / 错误三态；错误态附可复制的诊断信息
  - **模块内容深度**按 Q-001 裁定；推荐：代表性模块用 mock 数据实现真实形态——行情价格 = 盘面网格（含三态格：休市 / 待结算 / 缺数）、关注列表 = 通用数据表 + 迷你折线、数据发布日历 = 日程列表；其余四个模块为壳 + 示例占位
  - 模块内数值遵守 R-001 数值规则；行情价格是 v1 唯一使用涨跌专色的模块
- **验收规则**：
  - [ ] AC-004-1 七个模块在模块库中可见并可添加/移除；默认布局为七个（端到端）
  - [ ] AC-004-2 顺序调整与持久化（端到端：移动 → 刷新 → 顺序保持；移除 → 刷新 → 仍移除）
  - [ ] AC-004-3 模块壳结构契约：每个模块渲染统一结构（标题 / 副标 / 右注 / 状态徽 / 角标位），结构有自动检查（来历：FTEngine 图卡契约 CK-CARD）
  - [ ] AC-004-4 加载 / 空 / 错误三态可触发并显示；错误态含可复制诊断（组件测试）
  - [ ] AC-004-5 代表性模块的 mock 形态：盘面网格三态格、数据表数值对齐与涨跌字色、日程列表（组件测试 + 人工验收）
  - [ ] AC-004-6 栅格列宽不得用裸 `1fr`（静态检查；来历：FTEngine PG-1FR，图卡按 min-content 撑破列）

### R-005 AI 对话抽屉与 CoT 时间线

- **what**：
  - **底部固定输入栏**在任何页面可见；提交后抽屉向上展开覆盖内容区下部（两档高度 + 收起，推断见 Q-009）；抽屉是第三层玻璃
  - **时间线**：每次 agent 运行用时间线呈现——步骤类型包括思考摘要、工具调用、工具结果、文本输出、完成、失败；每步可展开看详情（推理全文、工具参数与结果摘要）
  - **后台运行**：运行中用户可切换页面或收起抽屉，运行不中断；回到抽屉时状态连续；输入栏显示运行中指示
  - **模块角标**：事件声明关联模块时，该模块壳显示角标（运行中 / 完成），用户查看后清除
  - **引导跳转**：事件可携带"建议跳转到模块/页面"，时间线出现可点击入口，点击后导航到目标并高亮模块
  - **事件流契约**：定义事件类型集合与字段（会话 id、步骤 id、类型、时间、模块关联、文本 / 工具摘要、终态）；mock 以脚本化回放提供，至少覆盖成功、失败、长时间运行三种脚本
- **验收规则**：
  - [ ] AC-005-1 输入栏全局可见；提交后抽屉展开并显示用户消息（端到端）
  - [ ] AC-005-2 时间线渲染 mock 事件流：步骤可展开/收起，终态（完成 / 失败）显示（组件测试）
  - [ ] AC-005-3 运行中切页不中断（端到端：开始运行 → 切到其他菜单 → 返回 → 时间线包含切走期间产生的步骤）
  - [ ] AC-005-4 模块角标随事件出现、变化（运行中 → 完成）、查看后清除（端到端）
  - [ ] AC-005-5 引导跳转：带跳转建议的事件生成入口，点击后导航并高亮目标模块（端到端）
  - [ ] AC-005-6 事件契约有类型定义与文档；mock 回放脚本覆盖成功 / 失败 / 长运行（契约测试）

### R-006 图表暗色主题

- **what**：
  - 由令牌生成图表（D-004）暗色主题并注册：画布透明、文字与轴线取界面令牌、序列色取黛驼暗色亮化版、区间带 / 均值 / 模型线对应亮化、退役色缺席
  - **黛驼亮化值**：保持原色序与色相身份（墨 → 主序列亮化为主文字色；茹藘 / 沙饧 / 苍艾 / 吐绶蓝 / 缥碧 / 碧落各自亮化），与背景对比度不低于登记阈值；亮化值登记为令牌并写入 `design/charts/` 的暗色适配记录（决定方式见 Q-003）
  - 至少一张样例折线图在模块中用主题渲染（mock 序列），作为 chart-templates feature 的主题基线
- **验收规则**：
  - [ ] AC-006-1 主题对象与令牌对拍（自动测试）；主题中不含退役色
  - [ ] AC-006-2 序列色对比度：每个亮化序列色对背景的对比度 ≥ 登记阈值（自动测试；阈值与算法随实现登记）
  - [ ] AC-006-3 样例图使用注册主题（端到端：图实例的序列色与令牌一致）
  - [ ] AC-006-4 画布透明、不出现白底块（自动：背景选项为透明；人工验收截图）

### R-007 数据访问契约与 mock

- **what**：
  - 前端读取的所有数据（焦点带日报摘要、模块数据、资讯、数据源状态、研究列表、模块库定义、agent 事件流与发送消息）经一层**类型化契约**访问；界面组件不直接发网络请求
  - 契约有两个实现：**mock**（内置示例数据与回放脚本，可按场景切换：正常 / 空 / 错误 / 延迟）与**真实实现**（本 feature 不交付，只留接口）；通过配置切换，默认 mock
  - 契约**文档化**（字段、语义、错误形态、分页与时间参数约定）并带版本号，作为 backend `api` feature 的输入
  - 契约中的数值字段带语义标注：单位、频率、涨跌语义（行情 / 分析）、截至时间，使界面不猜语义
- **验收规则**：
  - [ ] AC-007-1 界面层零直接网络调用（静态扫描：允许名单只含契约实现层）
  - [ ] AC-007-2 mock 场景切换：正常 / 空 / 错误 / 延迟四种场景可通过配置切换并被端到端测试使用
  - [ ] AC-007-3 契约文档与类型定义一致（契约测试：文档字段清单与类型定义对拍）
  - [ ] AC-007-4 契约数值字段带单位 / 频率 / 语义 / 截至时间（类型级约束 + 示例数据校验）

### R-008 规范资产移植登记

- **what**：
