# Feature: workbench-interaction（spec.md）

> Spec 阶段产物：按 **what/why** 写需求，不含技术方案。本文件只描述"要什么行为、如何验收"；
> 一切实现机制（框架用法、构建工具、测试框架、存储方式、文件组织等）在 `plan.md`。
> **阶段记录（2026-10-28）**：Spec 初稿，待 Clarify（Q-001~Q-012）与 **Gate 1** 批准；未批准前不进入 Plan。
> 需求来源：`docs/interaction.md`（交互权威）、`docs/designUI.md` §2.4/§3/§5.2/§7、D-016。

## 1. 背景与动机（why）

- 产品定位已由 D-016 / D-017 升级为「Agent+人 双循环工作台」：交付侧的主导对象是**作业**，四阶段（提取 → 处理 → 分析 → 交付）各设介入界面，交付物块式、版本化，人的介入事件化（`docs/interaction.md` §2–§3）。
- 现状与差距：`frontend-workbench` 交付的是"看"的地基——壳、设计系统、工作台模块、对话抽屉、数据访问契约；**没有"做"的对象**：没有作业、没有阶段轨道、没有采集/处理/分析/交付界面、没有交付物编辑与版本、没有介入记录。后端 `api` 与真实 pi agent 尚未就绪。
- 本 feature 交付 **Phase 1.5 协作交付骨架**（`docs/plan.md` §8）：让人"可在任意阶段介入但不干扰"从文档变成可验收的界面。v1 沿用 `frontend-workbench` 的交付模式——类型化契约 + mock 数据，真实后端与解析/闸门/agent 归后续 feature。

## 2. 目标与非目标

### 目标（what）

- **作业对象**：作业列表与详情（类型、状态、当前阶段、创建者、目标说明、创建/筛选/搜索）
- **四阶段轨道**：提取 / 处理 / 分析 / 交付，阶段状态与切换、待人工确认提示、显式重跑入口
- **采集台**：文件 / URL / 文本三种投放，来源说明（用途·可靠性·时效·口径），抽取预览与字段修正，待归属池
- **处理台**：加工配方只读展示、参数/口径修正、对账 diff、来源回溯、暂定标记
- **分析台**：结论卡 + 证据链、批注/追问/否决/深挖、轻量"教它一条规则"
- **交付台**：6 类块（结论/图表/表格/引用/待验证/备注）、块批注、结论与备注 inline 编辑、版本历史、diff、发布快照、来源徽/状态徽
- **介入事件与不干扰**：介入事件记录与历史、运行中编辑"待合并"标记（mock 事件流）、破坏性确认 / 非模态、角标与收件箱
- **契约扩展与 mock**：作业/阶段/产物/介入/交付物/版本的契约 v2 与场景化 mock
- **可验收性**：自动化检查 + 人工验收清单

### 非目标

- 验证性需求 / 验证队列、学习区、知识写入闸门、分析协议蒸馏、自学习（D-017 与后续 feature）
- 真实后端 `api` 实现、真实 pi agent 接入、真实文档解析/抽取/闸门（归 `api` / 知识库 feature）
- 完整自由块编辑器、图表/表格/引用块的编辑、PDF/图片导出（归图表与导出 feature）
- 导航菜单变更与工作台作业轨道本体（归 `frontend-workbench` spec v2；本 feature 只约定路由与入口，见 §4）
- 权限/多用户、移动端、无障碍专项、亮色主题

## 3. 需求条目

### R-001 作业对象与作业列表

- **what**：
  - 作业字段：标题、类型（日报 / 专题 / 临时）、品种 / 主题、目标说明、创建者（人 / 计划）、状态、当前阶段、更新时间、父作业 id（可空，为后续验证循环预留）
  - 状态枚举：`draft` / `collecting` / `processing` / `analyzing` / `delivering` / `delivered` / `needs_human` / `failed` / `cancelled`；阶段枚举：提取 / 处理 / 分析 / 交付
  - 作业列表：按状态 / 类型筛选、标题搜索、更新时间倒序；数据经契约 mock 读取
  - 新建作业：标题必填、类型必选、品种/主题可选、目标说明多行；创建后进入作业详情（阶段 = 提取，状态 = collecting）
  - 列表与详情具备加载 / 空 / 错误三态；列表路由可直达
- **验收规则**：
  - [ ] AC-001-1 作业列表渲染 mock 作业的标题、类型、状态徽、当前阶段、更新时间（组件测试）
  - [ ] AC-001-2 状态 / 类型筛选与标题搜索生效；筛选组合与清空可恢复（组件测试）
  - [ ] AC-001-3 新建作业：标题/类型必填校验，创建成功后进入详情且阶段=提取、状态=collecting（端到端，mock 契约记录创建参数）
  - [ ] AC-001-4 列表与详情的加载 / 空 / 错误三态可触发并显示，错误态含可复制诊断（组件测试）
  - [ ] AC-001-5 状态徽不只靠颜色区分（文案或图标），状态→文案映射由契约声明（组件测试 + 人工验收）

### R-002 四阶段轨道与作业详情

- **what**：
  - 详情页顶部阶段轨道：提取 → 处理 → 分析 → 交付；每阶段显示状态（未开始 / 运行中 / 待人工确认 / 已完成 / 冲突），当前阶段高亮
  - 点击阶段切换对应工作区；URL 携带阶段参数，刷新后停留在该阶段
  - "待人工确认"以横幅提示并给出处理入口（跳到对应阶段工作区）；不阻塞其他阶段的查看
  - 显式"重跑本阶段及下游"入口：二次确认（破坏性）→ 提交介入事件 → mock 模拟状态迁移；历史版本保留，介入历史可见
  - 作业级状态（needs_human / failed / cancelled）在详情页有明确展示与说明
- **验收规则**：
  - [ ] AC-002-1 阶段轨道按固定顺序渲染四阶段与各自状态；当前阶段高亮（组件测试）
  - [ ] AC-002-2 点击阶段切换工作区，URL 更新；直接打开带阶段参数的地址并刷新后仍停留该阶段（端到端）
  - [ ] AC-002-3 `needs_human` 时显示待人工确认横幅与处理入口，点击跳到对应阶段；其他阶段仍可查看（端到端）
  - [ ] AC-002-4 "重跑本阶段及下游"需二次确认；确认后 mock 状态迁移、生成一条介入事件并在介入历史可见（端到端）
  - [ ] AC-002-5 failed / cancelled 作业显示原因与可执行动作（重试入口 v1 仅占位并说明归属），不出现空白页（组件测试）

### R-003 采集台

- **what**：
  - 全局"投放"入口（顶栏，任意页面可用）+ 作业内采集台；两者进入同一投放流程
  - 三种投放：文件拖入 / 选择（白名单 pdf / docx / xlsx / md / csv）、URL 粘贴、文本粘贴（任一必填其一）
  - 来源说明表单：用途（必填，短文本）、可靠性（高 / 中 / 低 / 未知）、时效（发布日期 / 有效期）、口径备注（可选）
  - 提交后显示 mock 抽取预览：识别类型、字段 / 列映射、单位、时间范围；可修正字段映射与单位后确认入库
  - 未指定作业的投放进入"待归属池"，可从池中归入某个作业
  - 抽取结果状态展示：待验证 / 已入库 / 隔离（mock 值；真实闸门非本 feature）
- **验收规则**：
  - [ ] AC-003-1 全局投放入口在作业列表、作业详情、工作台可用，进入同一投放流程（端到端）
  - [ ] AC-003-2 三种投放方式均可用；文件类型白名单外给出可操作提示（组件测试）
  - [ ] AC-003-3 用途必填校验；来源说明随投放记录提交（端到端，断言契约 payload）
  - [ ] AC-003-4 mock 抽取预览展示类型 / 映射 / 单位 / 时间范围，修正后确认才入库（组件测试）
  - [ ] AC-003-5 未指定作业的投放进入待归属池，归入作业后出现在该作业的采集列表（端到端）
  - [ ] AC-003-6 抽取结果状态（待验证 / 已入库 / 隔离）可见且不只靠颜色（组件测试）

### R-004 处理台

- **what**：
  - 展示本作业的数据源与序列、加工配方步骤（只读列表 / 单链 DAG）、每个派生值可回溯来源（观测或表行）
  - 参数 / 口径修正：单位、时区 / 日历、重采样、聚合方式；提交生成介入事件，产物标"待合并"
  - 对账 diff：同一序列两来源的差异视图（表格 + 差异高亮）
  - "标记暂定"操作：该产物在下游显示"暂定"状态徽
- **验收规则**：
  - [ ] AC-004-1 处理台渲染数据源 / 序列 / 配方步骤；派生值可打开来源回溯（组件测试）
  - [ ] AC-004-2 参数修正提交后生成介入事件，产物出现"待合并"标记（端到端，断言事件 kind）
  - [ ] AC-004-3 对账 diff 展示两来源差异并高亮，空 diff 有说明（组件测试）
  - [ ] AC-004-4 "暂定"标记生效并在下游状态徽体现（组件测试）
  - [ ] AC-004-5 无数据 / 配方为空 / 错误三态可显示（组件测试）

### R-005 分析台

- **what**：
  - 结论卡列表：结论文本、证据链数量、状态徽、来源徽
  - 选中结论查看证据链（断言 / 序列 / 来源锚），可跳转来源
  - 介入动作：批注（结论级）、追问（"依据？" / "如果…"）、要求深挖、删除、否决；均记录为介入事件（kind 对应 interaction §3.4）
  - 轻量"教它一条规则"入口：写一条规则备注并标为候选（显式教导），记录为介入事件
  - 作业上下文追问通过全局对话抽屉发起：显示 job_id / stage 上下文标识，事件流由 mock 回放
- **验收规则**：
  - [ ] AC-005-1 结论卡列表与状态 / 来源徽渲染，证据链数量正确（组件测试）
  - [ ] AC-005-2 打开结论证据链并可跳转来源锚（组件测试）
  - [ ] AC-005-3 批注 / 追问 / 深挖 / 删除 / 否决各自生成对应 kind 的介入事件（端到端，断言事件类型与 payload）
  - [ ] AC-005-4 "教它一条规则"生成候选规则事件，标注为 candidate（组件测试）
  - [ ] AC-005-5 对话抽屉在作业内显示作业 / 阶段上下文标识；mock 事件流可回放（端到端）
  - [ ] AC-005-6 加载 / 空 / 错误 / 冲突态可显示（组件测试）

### R-006 交付台

- **what**：
  - 块类型：结论 / 图表 / 表格 / 引用 / 待验证 / 备注；v1 块顺序只读（排序后置）
  - 渲染：结论/引用/备注为文本块；图表块用契约提供的 chart-spec 样例渲染（完整模板归 chart-templates）；表格块为只读表格
  - 编辑：结论与备注文本可 inline 编辑 → 生成新 revision（来源徽 = 人）；图表/表格/引用块只读
  - 块批注：线程、未解决 / 已解决
  - 版本历史：版本号 / 作者 / 时间 / 摘要；可查看任一历史版本（只读）
  - diff：选择两个版本，按块展示文本差异与变更摘要
  - "向 agent 下改稿指令"：选择块 + 指令文本 → 记录介入事件；mock 回放一条 agent 改稿事件生成新版本（来源徽 = agent），可接受 / 回退
  - 发布：二次确认 → 生成发布快照、作业状态置 delivered、显示发布信息；发布视图只读
  - 块级来源徽 / 状态徽常驻
- **验收规则**：
  - [ ] AC-006-1 六类块按契约顺序渲染；图表块使用契约 chart-spec 与既有暗色主题（组件测试 + 人工验收）
  - [ ] AC-006-2 结论 / 备注 inline 编辑生成新 revision，来源徽=人；图表 / 表格 / 引用块不可编辑（组件测试）
  - [ ] AC-006-3 块批注可新建 / 回复 / 标记已解决（端到端）
  - [ ] AC-006-4 版本历史列表与历史版本只读查看（端到端）
  - [ ] AC-006-5 两版本 diff 按块展示文本差异与变更摘要（组件测试）
  - [ ] AC-006-6 改稿指令生成介入事件；mock 回放后新版本来源徽=agent，可接受 / 回退（端到端）
  - [ ] AC-006-7 发布需二次确认；发布后生成快照、作业置 delivered、视图只读（端到端）
  - [ ] AC-006-8 每个块显示来源徽与状态徽（组件测试）

### R-007 介入事件、版本与不干扰

- **what**：
  - 介入事件契约字段：`id / job_id / stage / artifact_id / base_rev / kind / payload / reason / outcome / created_at`；作业详情侧栏"介入历史"按时间展示，可按阶段 / 类型筛选
  - 运行中编辑"待合并"：由 mock 事件流驱动（agent 运行开始 → 人编辑 → 产物显示"待合并"；mock 检查点完成事件 → 变"已合并"）
  - 无模态：编辑 / 批注 / 投放不弹模态；仅删除来源、发布、取消作业等破坏性动作二次确认
  - 角标与收件箱：作业列表 / 轨道显示待处理介入角标；收件箱可查看并清除
  - 玻璃层级不新增第四层（沿用 frontend-workbench 静态守卫）
- **验收规则**：
  - [ ] AC-007-1 介入历史渲染 mock 事件，字段齐全，可按阶段 / 类型筛选（组件测试）
  - [ ] AC-007-2 mock 运行中编辑出现"待合并"标记，检查点事件后变为"已合并"（端到端）
  - [ ] AC-007-3 正常编辑 / 批注 / 投放不出现模态确认；删除 / 发布 / 取消作业出现二次确认（端到端）
  - [ ] AC-007-4 待处理介入角标在作业列表 / 轨道出现，查看收件箱后清除（端到端）
  - [ ] AC-007-5 玻璃层级 ≤3 的静态检查通过（静态检查）

### R-008 契约扩展与 mock

- **what**：
  - 在 `frontend-workbench` 数据访问契约基础上扩展 v2：作业、阶段、产物、介入事件、交付物、版本、投放、agent 事件（带 job_id / stage）
  - mock 场景：正常 / 空 / 错误 / 延迟 + 作业运行中 / 待人工确认 / 冲突 / 已交付
  - 契约文档与类型定义一致；界面层零直接网络调用
  - 真实实现（backend `api`）非本 feature，仅留接口
- **验收规则**：
  - [ ] AC-008-1 契约文档字段清单与类型定义对拍一致（契约测试）
  - [ ] AC-008-2 场景切换可用（正常 / 空 / 错误 / 延迟 / 运行中待合并 / 冲突 / 已交付），并被端到端测试使用（契约测试 + 端到端）
  - [ ] AC-008-3 界面层零直接网络调用（静态检查，允许名单只含契约实现层）
  - [ ] AC-008-4 契约扩展版本号与变更说明登记（契约文档）

### R-009 可验收性

- **what**：
  - 自动化：单元 / 组件 / 端到端 + 静态守卫（状态徽不只靠颜色、来源徽覆盖、零直接网络调用、玻璃层级继承、无裸颜色字面量继承）
  - 人工验收清单（视觉与交互）随实现提交，Handoff 时逐项附截图
- **验收规则**：
  - [ ] AC-009-1 一条命令运行全部自动化检查并全绿（命令随实现登记）
  - [ ] AC-009-2 人工验收清单存在，每项有"看什么"描述，Handoff 附截图证据
