# Feature: data-layer（spec.md）

> Spec 阶段产物：按 **what/why** 写需求，不含技术方案。本文件只描述"要什么行为、如何验收"；
> 一切实现机制（存储引擎、算法、传输方式、表结构、锁机制等）在 `plan.md`。
> **Gate 1 记录**：2026-10-26 首版批准（Walter）；经十五轮双审修订（Q-005~Q-032、D-012 ADR）；同日按 Walter 要求完成去技术化重写。**待重新批准后冻结。**

## 1. 背景与动机（why）

四个产品痛点中，数据分散、不可追溯、无法按需取数都压在数据层上：

- 多供应商时间序列拼图（痛点 1）需要"标准序列 + 多源归并"；
- agent 按指令单次/实时提取并更新数据库（docs/plan.md §7.3）需要按需取数模式；
- 平衡表等信息可追踪（痛点 3）需要观测级溯源与对账；
- 日报、图表、知识库表格全部依赖统一序列目录。

本 feature 交付**统一数据层骨架**，是后续所有 feature 的地基（D-005 / D-006）。范围与语义裁定权威见 D-012 ADR。

## 2. 目标与非目标

### 目标

- 声明式数据源适配器框架：源以声明清单接入，程序自动编译序列目录
- 序列身份：描述符（asset/geo/measure + 可选 contract）派生稳定 ID；别名映射；同描述符自动归并
- 观测存储：追加写、幂等重放、当前值/历史时点查询、多源择优（唯一确定的全序）
- 取数模式：定时批量骨架 + 按需取数；实时仅保留接口
- 溯源与对账：每个值可查来源与批次；批次间可生成 diff；同序列多源口径自动检查
- v1 内置数据源：akshare（能源品种行情/仓单）、EIA（公开能源数据）、本地文件（CSV/Excel 向导映射）
- agent 工具（经 MCP 暴露给 pi）：search_series / fetch_series / list_sources / reconcile
- 凭证本地加密存储，保存与读取失败均拒绝（fail closed）；代码零凭证字面量
- 最小 CLI 配置入口（开发/测试期；正式 GUI 归 settings feature）

### 非目标

- realtime 行情流实现（Phase 2）
- 品种业务模型（供需/物流/平衡表口径 —— 后续 domain feature）
- 前端数据源配置界面（归 settings feature；本 feature 只交付 **CLI 入口**）
- **任何面向前端的 HTTP API**（MCP 通道与 CLI 内部只读通道属本 feature 内部接口，不构成前端 API）
- 第三方适配器生态与安装市场（Phase 4）
- 统一交易日历（v1 存原始时间戳 + freq 标记）

## 3. 需求条目

### R-001 适配器框架

- **what**：适配器 = 源声明清单 + 取数实现。程序启动时扫描内置与用户适配器目录，自动编译序列目录；每个源可被单独启用/停用。
- **验收规则**：
  - [ ] AC-001-1 内置适配器目录与用户适配器目录均可被扫描并加载
  - [ ] AC-001-2 清单校验：缺失/非法字段的适配器被拒绝并报告原因，不影响其他适配器（合法性规则：必填字段与合法值域，在 plan §2.1 定稿并随实现固定）
  - [ ] AC-001-3 新增/移除适配器后，序列目录在下次启动（或显式 reload）时**增量重建**：既有序列不清空、不丢失；校验失败（含不可解析）= 该源标 error（无论此前状态），数据保留；目录中消失 = 该源标 disabled（软删），数据保留且历史仍可查询
  - [ ] AC-001-4 重复源 id：先加载者生效，后到者标 error 并报告（不影响先加载者与其他适配器）

### R-002 序列身份

- **what**：规范身份 = **描述符 {asset, geo, measure, contract?}**（asset/geo/measure 必填且非空；contract 可选：缺省表示主力/连续序列，非空表示指定合约，合法值 = 1–20 位字母或数字）派生的**稳定 ID**（派生算法与规范化规则见 plan §2.3；ID 确定、跨重启/跨机器/跨实现稳定，配 golden 对拍）。unit/freq/tz 属于序列元数据，不参与身份。显示格式沿用 8 槽约定（槽位映射见 plan §2.3）。别名映射：源侧符号 → 描述符（模板规则 + 模糊匹配 + 手动覆盖），带来源作用域，裁决顺序：**手动 > manifest > 模板 > 模糊**。
- **验收规则**：
  - [ ] AC-002-1 同一描述符派生的 ID 确定且稳定（golden 对拍）
  - [ ] AC-002-2 两个来源声明同一描述符（含 contract）→ 自动归并到同一序列；不同 contract 值 = 不同序列；unit/freq 不同仍归并，差异进对账（R-006）
  - [ ] AC-002-3 别名映射可被用户手动覆盖，覆盖持久化；别名带来源作用域；冲突按"手动 > manifest > 模板 > 模糊"裁决
  - [ ] AC-002-4 同一 ID 永不手写分配（构造性检查：ID 仅由唯一派生函数产出；辅助静态检查规则与样例随实现提交）
  - [ ] AC-002-5 8 槽显示 ID 由描述符 + freq 元数据渲染，含 golden 对拍

### R-003 观测存储与择优

- **what**：
  - 观测**追加写、永不删行**；**幂等**：同一批次重放不产生重复观测、不覆盖已保留历史
  - 当前值查询：每 `(序列, 时间点)` 按择优规则取当前版本；每序列最新时间点的择优值
  - 历史时点查询：返回"任一时点所见"（该时点前已可见的数据，按同一择优规则），且与当前值查询在"现在"时点一致
  - **择优 = 唯一确定的全序**：优先级数值小者胜 → 数据可见时间新者胜 → 批次序号大者胜；**手动覆盖 = 替换该源的优先级值、参与同一决胜链（不存在独立于决胜链的绝对覆盖）**；v1 基础版（FTEngine 五层分类留待平衡表 feature，D-012）
  - 择优候选 = **全部源的观测行**（源被停用/报错不改变历史数据的可见性）；源状态只影响配置角色（主源/默认拉取源/展示口径）
  - 数据可见时间 = 批次成功写入的时刻；实际拉取时间单独记录
  - 历史择优使用**当前**配置（历史配置版本化留 Phase 2，明确不承诺）
- **验收规则**：
  - [ ] AC-003-1 同批次重放不产生重复行、不覆盖历史
  - [ ] AC-003-2 当前值查询两粒度正确：每 (序列, 时间点) 择优值；每序列最新时间点择优值
  - [ ] AC-003-3 历史时点查询与当前值查询使用同一择优规则（"现在"时点两者一致）
  - [ ] AC-003-4 择优全序确定性：优先级小 → 可见时间新 → 批次序号大；手动覆盖 = 替换优先级参与决胜链（构造并列样例断言唯一结果）

### R-004 取数模式

- **what**：
  - **scheduled 骨架**：任务可注册/查看/手动触发（完整调度器随 daily-report feature 引入，D-012）
  - **on_demand**：按需取数能力——调用方**必须显式指定 do_fetch**；true 触发即时拉取 → 写库 → 返回；拉取来源参数仅作用于取数分支（缺省 = 启用源中优先级数值最小者，并列取注册顺序先者；**取数分支无启用源 → 返回 not_found**；显式指向非启用源 → 校验错误）；**只读分支忽略来源参数**（返回跨源择优结果，源状态不影响历史可见性）。"启用源"定义 = 状态 ok 且已启用（判定细则见 plan）
  - **失败原子性**：批次在拉取前创建；拉取/归一化/写入任一环节失败 → 本批次不产生部分写入、批次标记失败；已有成功批次不回退；可重试错误支持手动重试 = 新批次
  - **单写者**：同一数据目录同时只允许一个写进程（写操作冲突时报错提示）；只读不受影响（机制见 plan）
- **验收规则**：
  - [ ] AC-004-1 按需取数行为符合 what 中的 do_fetch/source 语义（含只读分支与显式源校验）
  - [ ] AC-004-2 任务可注册/查看/手动触发（CLI 提供入口）
  - [ ] AC-004-3 失败原子性：任一环节失败无部分写入、批次标记失败；重试 = 新批次
  - [ ] AC-004-4 realtime 仅定义接口签名（实现与网络行为不在 v1）
  - [ ] AC-004-5 CLI 可配置数据源并持久化（重启后生效）；只能配置已有清单的源（新增源 = 生成清单骨架）
  - [ ] AC-004-6 单写者：写进程冲突时报错提示；只读命令不受影响

### R-005 溯源与 diff

- **what**：每个观测值可回答"哪来的、何时拉取、哪一批"；批次记录覆盖范围与口径快照。**diff 仅在两个成功批次、同序列、同源、覆盖范围相同、口径快照一致时可比**，否则报告不可比原因而非误报删除。diff 语义：A 有 B 无 = 删除；B 有 A 无 = 新增；数值变化 = 修订；变化量汇总仅统计修订类，新增/删除只计数量。
- **验收规则**：
  - [ ] AC-005-1 任意观测可查询其来源/拉取时间/批次/原始载荷哈希（CLI `provenance` 命令可执行）
  - [ ] AC-005-2 可比批次的 diff 输出新增/修订/删除三类计数与变化量汇总（口径见 what）；不满足可比条件 → 报告不可比原因（CLI `diff` 命令可执行）

### R-006 对齐校验

- **what**：同序列多源自动检查单位、时区/日历、重采样口径。**口径声明以源清单为唯一权威**（目录中的派生值冲突时以清单为准并出对账提示）。展示口径跟随主源（启用源中优先级数值最小者，并列取注册顺序先者；**主源候选为空 → 沿用最后一次展示口径并对账报告标 warning；无历史口径 → 置空并说明**）。不一致进对账报告，不静默换算。
- **验收规则**：
  - [ ] AC-006-1 两源同序列且清单声明单位不同 → 对账报告提示（不静默换算），展示口径跟随主源
  - [ ] AC-006-2 时区/频率声明不一致 → 对账报告提示
  - [ ] AC-006-3 对账结果可查询（reconcile 工具）
  - [ ] AC-006-4 主源候选为空 → 展示口径沿用末次值/置空 + 对账报告 warnings 非空并注明原因

### R-007 内置数据源

- **what**：akshare（能源板块核心品种 SC/FU/LU/BU/PG 主力与连续合约日线 + 交易所仓单/库存日报）、EIA（能源公开数据，用户自带 API key）、本地文件（CSV/Excel 向导式列映射，向导 = CLI 交互，映射可保存复用）。更多数据源/板块后续按适配器机制新增（新增品种/枚举值须先修订本 spec 过 Gate）。
- **验收规则**：
  - [ ] AC-007-1 akshare 能拉取指定合约/连续合约日线以及仓单/库存日报并入库（离线测试用固定响应样本）
  - [ ] AC-007-2 EIA 使用用户配置的 key 拉取公开数据集并入库（key 读取失败 → 报错；测试用固定响应样本）
  - [ ] AC-007-3 本地 CSV/Excel 经 CLI 向导映射入库，映射可保存复用
  - [ ] AC-007-4 任一适配器失败不影响其他适配器与程序运行

### R-008 agent 工具（MCP）

- **what**：data 工具集经 MCP 暴露给 pi：`search_series`（匹配描述符字段与别名；soft_deleted 序列仍可检索）、`fetch_series`（默认只读短路：不触发拉取、不写库；显式取数标志才触发）、`list_sources`、`reconcile`。成功返回结构化结果（逐工具契约见 plan §2.2）；错误统一结构化（含错误码、消息、可重试标记；映射固定，见 plan §2.2）。
- **验收规则**：
  - [ ] AC-008-1 四工具可经 MCP 调用并返回各自契约的结构化结果
  - [ ] AC-008-2 fetch 默认 false：只读短路（不触发拉取、不写库）；显式 fetch 标志才取数写库
  - [ ] AC-008-3 错误返回结构化（含错误码/消息/可重试标记，映射固定；不抛裸异常给模型）
  - [ ] AC-008-4 MCP 服务可启动并连接（生命周期入口见 plan）

### R-009 凭证与隔离

- **what**：凭证存用户数据目录并**加密**；**保存与读取两条路径均 fail closed**（加密不可用 = 拒绝保存并报错；读取/解密失败 = 报错，禁止明文或空值返回）；代码零凭证字面量（静态扫描规则与阳/阴性样例随实现提交）；每安装独立数据目录，用户数据不入 Git。
- **验收规则**：
  - [ ] AC-009-1 凭证文件不含明文；保存失败与读取失败两条路径均报错
  - [ ] AC-009-2 代码库零凭证字面量（静态扫描可复现：规则与样例随测试提交，阳性样例须命中规则）
  - [ ] AC-009-3 数据目录结构与 plan §3.3 权威布局一致；用户数据不入 Git
