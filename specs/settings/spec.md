# Feature: settings（spec.md）

> Spec 阶段产物：按 **what/why** 写需求，不含技术方案。本文件只描述"要什么行为、如何验收"；
> 一切实现机制在 `plan.md`。
> **Gate 1 记录**：v1 草案（2026-10-27），待 Walter 批准。
> 依赖：data-layer（凭证加密存储、数据源与序列目录、状态与来源查询）。

## 1. 背景与动机（why）

data-layer v1 只交付了 CLI 配置入口（`config credentials`），非技术用户无法完成"填档案 → 开通数据源 → 看到数据"的闭环。同时：

- EIA 等数据源需要 API key 才能用官方接口，而注册需要姓名、邮箱、组织类型，用户每次都要重新找、重新填；
- 没有 key 时数据层会自动回退到免凭证来源（data-layer spec R-007），但用户看不到"当前走的是哪条路径、为什么"，容易误以为数据不新；
- 用户对"我的信息存在哪里、传没传出去"没有可见答案。

本 feature 交付**用户档案 + 首次启动引导 + 数据源开通向导**，让非技术用户零文档上手，同时把"档案仅存本机"变成可验证的产品行为。

## 2. 目标与非目标

### 目标

- 首次启动时收集用户档案；档案有必填项与可选项，缺失时明确提示
- 档案仅存本机、不上传、可查看/修改/清除
- 数据源开通向导：以档案预填 → 用户自行在浏览器提交 → 回填 key → 立即验证 → 加密保存
- 数据源状态可见：路径（API / 免凭证回退）、最近一次验证结果、失败的可操作指引
- v1 只服务 EIA 一个"需要凭证的数据源"，但机制不写死单一数据源

### 非目标

- 程序代替用户提交数据源注册表单、代替用户勾选服务条款
- 接入用户邮箱（IMAP 等）自动收取 key
- 档案云端同步 / 多设备同步
- 其他数据源的开通向导（后续按同一机制扩展）
- 数据源本身的取数与存储（归 data-layer）

## 3. 需求条目

### R-001 用户档案

- **what**：用户档案包含身份与联系信息，以及数据源注册所需的组织属性。字段分三类：
  - 必填（数据源注册必需）：名、姓、邮箱、组织类型
  - 可选：用途说明、是否接收数据源通知
  - 应用偏好（非注册必需）：界面显示名
  档案**仅存本机、不上传**；用户可随时查看、修改、清除；清除后相关凭证仍保留（凭证与档案相互独立），但向导将要求重新填写档案。
- **验收规则**：
  - [ ] AC-001-1 档案字段齐备且可保存/读取；必填缺失时拒绝保存并指出缺失项
  - [ ] AC-001-2 邮箱格式校验；组织类型取值来自固定清单（与数据源注册表单的选项一致）
  - [ ] AC-001-3 档案仅存本机：不产生任何网络请求即可完成填写与保存；存储位置在用户数据目录内、不入 Git
  - [ ] AC-001-4 清除档案后，已保存的凭证仍可用（互不影响）

### R-002 首次启动引导

- **what**：应用首次启动时进入引导流程：展示档案表单（预填可从系统区域设置推断的项，如界面语言），必填项未完成不能继续；用户完成或明确选择"稍后填写"后进入主界面。"稍后填写"不阻塞使用免凭证数据源，但数据源开通向导与需要凭证的功能会提示先补档案。
- **验收规则**：
  - [ ] AC-002-1 首次启动（档案不存在）进入引导；档案已存在则不再重复引导
  - [ ] AC-002-2 必填项未填 → 不能完成引导，逐项提示
  - [ ] AC-002-3 选择"稍后填写" → 进入主界面；此后可从设置再次进入引导补填
  - [ ] AC-002-4 引导可中断并恢复：已填内容不丢失（不要求跨进程崩溃恢复，只要求同一次运行内不丢）

### R-003 数据源开通向导（EIA）

- **what**：向导分五步，每步有明确结果：
  1. **准备**：用档案预填数据源注册所需的字段；档案缺项时先补档案
  2. **提交**：给出数据源注册页地址与逐项填写指引；由用户在浏览器中自行核对、勾选条款并提交（程序不代提交）
  3. **取回**：提示"key 已发送到邮箱"；用户把收到的 key 粘贴回程序
  4. **验证**：立即用该 key 发起一次真实取数验证；成功才保存
  5. **完成**：显示数据源当前状态（走 API）、最近验证时间；提供"重新验证""更换 key""清除 key"
- **验收规则**：
  - [ ] AC-003-1 向导预填内容与档案一致；档案缺字段时先引导补档案，不出现空表单
  - [ ] AC-003-2 验证成功才保存凭证；验证失败给出可操作原因（无效 key / 网络不可达 / 服务端错误可重试 / 已达到限额），不保存无效 key
  - [ ] AC-003-3 粘贴的 key 不回显明文（输入框遮蔽），流程中与日志中均不出现明文
  - [ ] AC-003-4 完成页如实显示当前取数路径（API）与最近验证时间
  - [ ] AC-003-5 支持更换/清除 key；清除后该数据源自动回到免凭证路径，界面明确提示"当前为免凭证回退"

### R-004 数据源状态可见

- **what**：数据源列表对每个源显示：名称、启用状态、当前取数路径（API / 免凭证回退 / 仅声明不可取数）、最近验证或取数时间、不可用原因（如缺少凭证、凭证不可读、上游报错）。
- **验收规则**：
  - [ ] AC-004-1 每个数据源的状态字段可读、与 data-layer 的源状态一致
  - [ ] AC-004-2 凭证存在但不可读时，状态为错误并给出原因（不回退、不静默）
  - [ ] AC-004-3 未配置凭证时，状态明确标注"免凭证回退"，不显示为正常 API 路径

### R-005 隐私与安全边界

- **what**：程序不代替用户接受第三方条款、不代提交注册表单、不读取用户邮箱；档案与凭证都不进入 Git、不上传，任何界面不显示凭证明文。
- **验收规则**：
  - [ ] AC-005-1 开通向导的每一步都不存在"程序自动提交注册表单"的行为（无表单代提交代码路径）
  - [ ] AC-005-2 档案与凭证文件不出现在版本库中（静态检查 + 目录断言）
  - [ ] AC-005-3 界面/日志/错误消息中不含凭证明文（阳性样例验证）

## 4. 约束与依赖

- 依赖 data-layer v23：凭证加密存储与 fail closed、数据源状态查询、EIA 双路径（API / 免凭证回退）
- 依赖 desktop-shell 提供窗口与设置入口（本 feature 的界面宿主）
- 环境：Windows 11；档案与凭证仅存本机
- 相关决策：D-014（EIA 双路径与档案归属）、D-007（桌面外壳）、D-011（UI 体系）
