# Feature: desktop-shell（spec.md）

> Spec 阶段产物：按 **what/why** 写需求，不含技术方案。本文件只描述"要什么行为、如何验收"；
> 实现机制（外壳技术选型、进程管理、打包、更新通道等）在 `plan.md`。
> **Gate 1 记录**：v1 草案（2026-10-28），待 Walter 批准。
> 依赖：`frontend-workbench`（前端壳与设计系统）、`settings`（引导与档案核心）、`data-layer v23`（后端数据服务）、`docs/interaction.md`（双循环与作业模型）。

## 1. 背景与动机（why）

v2 把产品定位为 **Agent+人 的本地研究工作台**（`docs/plan.md` §2）：以「作业」为一等对象，交付循环与学习循环共享带溯源的知识底座。桌面应用是唯一交付形态（D-001），因此外壳不是"套个窗口"，而是**用户接触整个工作台的第一层**：

- 用户安装后双击即用，不需要装 Python/Node、不需要命令行；
- 后端（数据服务、agent、作业引擎）是本地进程，用户看不见，但它的启停、失败与恢复必须**可见、可解释**；
- 首启引导（`settings` 的 GUI 类 AC）与导航容器（`workbench-interaction` 的工作台/作业/学习三区）都以本 feature 为宿主；
- 作业可能长时间运行，用户会关窗、切走、最小化——外壳要保证"作业不因交互而丢"。

现状：后端已有 data-layer（已合并）与 settings 核心（已合并，GUI 未做）；前端在 `frontend-workbench` 分支（mock 验收，未接真实 API）；本 feature 是把三者装成"一个能交付给其他交易者的应用"的那一层。

## 2. 目标与非目标

### 目标

- **装完即用**：单个安装包，双击启动；目标机器无需预装运行时
- **可解释的启动与失败**：启动过程有进度与就绪判定；失败给出可操作原因（不是白屏、不是裸错误）
- **进程生命周期正确**：启动/退出按序，异常退出后下次启动能自愈（不留锁、不留孤儿进程、不占端口）
- **单实例与数据目录唯一**：同一用户的多个启动请求收敛到一个窗口，不产生第二个写进程
- **首启引导与设置入口**：承载 `settings` 的界面类 AC
- **后台作业可见**：托盘/通知反映"运行中/待处理/出错"，关窗不等于丢作业
- **可更新、可诊断**：版本检查与更新提示；崩溃可导出脱敏诊断包
- **安全边界清晰**：只服务本机、不加载远程内容、不上传用户数据

### 非目标

- 前端页面与交互实现（工作台、作业详情、学习区、图表）→ `frontend-workbench` / `workbench-interaction`
- 后端业务 API 与真实数据契约 → `api` feature
- agent 能力本身（pi 集成、工具、协议蒸馏）→ 后续 agent 相关 feature
- 多窗口 / 多用户 / 远程访问（后续移动端只读通道另立）
- 自动更新服务端与灰度发布（v1 只做客户端检查与提示）
- 本地模型随包分发（D-009 的模型体积问题另行决策）

## 3. 需求条目

### R-001 安装与首次启动

- **what**：用户拿到安装包后完成安装并启动应用；目标机器未安装 Python/Node 也能运行。首次启动进入引导（见 R-005）；非首次启动直接进入工作台。
- **验收规则**：
  - [ ] AC-001-1 在未安装开发环境的干净 Windows 机器上，安装包可完成安装并成功启动到可见界面
  - [ ] AC-001-2 启动过程有可见进度或骨架界面，不出现长时间白屏；冷启动在基准机器上 15 秒内出现可交互界面
  - [ ] AC-001-3 卸载后不残留运行时文件；用户数据目录按 R-004 的约定保留或提示是否删除
  - [ ] AC-001-4 安装包内不含任何用户数据、凭证或开发期产物

### R-002 后端托管与就绪

- **what**：外壳负责拉起本地后端（数据服务与 agent 宿主）并判断"就绪"。就绪 = 后端健康检查通过且数据服务可用；**不以"端点文件存在"或"端口可连"单独作为就绪依据**。后端未就绪时界面明示状态并可重试，前端不白屏。
- **验收规则**：
  - [ ] AC-002-1 后端未启动完成时，界面显示"正在启动/未就绪"而非空白或报错
  - [ ] AC-002-2 就绪判定使用后端健康检查；把健康检查置为失败时，外壳不进入"就绪"状态
  - [ ] AC-002-3 后端崩溃后外壳自动重启（有次数上限）；达到上限后给出明确错误与"导出诊断"入口
  - [ ] AC-002-4 前端可在**没有后端**的情况下启动并进入 mock 模式（供前端验收），不因后端缺席而无法打开

### R-003 生命周期与退出

- **what**：启动按固定顺序（外壳 → 后端 → 就绪 → 前端可交互）；退出按相反顺序，确保数据服务释放写锁与端口。存在运行中作业时退出需提示（等待完成 / 取消退出）。异常终止（强杀、断电）后，下次启动能自愈：陈旧锁被回收、占用端口可换用、未完成批次按后端既有约定处理。
- **验收规则**：
  - [ ] AC-003-1 正常退出后，数据目录不残留写锁文件、后端端口已释放
  - [ ] AC-003-2 存在运行中作业时关闭应用，出现提示且选择"取消退出"后作业继续
  - [ ] AC-003-3 强杀外壳后再启动，应用能正常进入就绪（陈旧锁被回收）
  - [ ] AC-003-4 退出过程中不再接受新作业，已排队任务被明确标记（不静默丢弃）

### R-004 单实例与数据目录

- **what**：同一用户在同一时刻只有一个应用实例在运行服务；再次启动时聚焦已有窗口而不是启动第二个后端。数据目录默认位于用户本地应用数据区，可在设置中更改（更改后需重启生效）。数据目录不可写或被其他进程占用时，给出明确原因与处理建议，不静默降级到临时目录。
- **验收规则**：
  - [ ] AC-004-1 应用运行中再次双击启动 → 已有窗口被聚焦，不产生第二个后端进程与第二个数据服务
  - [ ] AC-004-2 数据目录被另一个写进程占用时（例如手工 CLI 正在写），启动给出"另一进程占用"的明确提示，而不是无响应或静默失败
  - [ ] AC-004-3 数据目录不可写（权限/只读盘）时启动失败并指出具体路径与原因
  - [ ] AC-004-4 更改数据目录后重启，应用在新目录就绪；原目录数据不被删除

### R-005 首启引导与设置入口

- **what**：承载 `settings` 的界面类需求：首次使用进入引导（档案可留空、可跳过），引导完成后不再重复；设置入口在应用内常驻可达，包含用户档案、数据源开通向导与数据源状态。引导与设置的业务逻辑复用 `settings` 核心，外壳只提供界面宿主与导航。
- **验收规则**：
  - [ ] AC-005-1 无档案且引导未完成 → 首次启动进入引导；完成后再次启动不再进入
  - [ ] AC-005-2 引导可跳过并进入主界面；跳过后可从设置再次进入补填
  - [ ] AC-005-3 设置内可完成数据源开通（预填、粘贴 key、验证、保存）并看到数据源当前状态（含"未配置 → 免凭证回退"）
  - [ ] AC-005-4 凭证明文不出现在界面、日志与诊断包中

### R-006 后台状态、托盘与通知

- **what**：应用最小化/关闭窗口后，运行中作业继续；托盘图标反映状态（空闲 / 运行中 / 有错误）。系统通知覆盖：作业阶段完成、出现待处理的验证性需求、介入冲突待合并、后端异常。通知可关闭；关窗行为可配置（退出 / 最小化到托盘）。
- **验收规则**：
  - [ ] AC-006-1 作业运行中关闭窗口（最小化模式）→ 作业继续，托盘显示运行中
  - [ ] AC-006-2 作业阶段完成时发出系统通知（通知开启时）
  - [ ] AC-006-3 通知可在设置中关闭，关闭后不再弹出（托盘状态仍在）
  - [ ] AC-006-4 托盘菜单可打开主窗口、查看运行中作业、退出应用

### R-007 故障与恢复

- **what**：对可预期的失败给出可操作处理，而不是崩溃或白屏：后端端口被占用、后端启动超时、前端资源加载失败、磁盘写满。
- **验收规则**：
  - [ ] AC-007-1 默认端口被占用 → 自动改用其他端口并成功就绪（或明确提示可改端口），不静默失败
  - [ ] AC-007-2 后端启动超时 → 显示超时原因与"重试/查看日志"，不停留在加载态
  - [ ] AC-007-3 前端资源缺失或加载失败 → 显示可操作错误页（重试、打开日志），不白屏
  - [ ] AC-007-4 磁盘写满导致写入失败 → 界面提示具体原因，应用不崩溃

### R-008 更新与版本

- **what**：应用显示当前版本；启动后可按配置检查新版本并提示（不静默自动安装）。更新包与安装包的完整性可校验。
- **验收规则**：
  - [ ] AC-008-1 设置/关于页显示当前版本与构建信息
  - [ ] AC-008-2 有可用更新时提示版本号与更新说明，用户可选择稍后
  - [ ] AC-008-3 更新检查失败（离线）不阻塞使用，不弹错误弹窗

### R-009 安全边界

- **what**：本地服务仅监听回环地址；访问令牌只对本机进程可见；渲染层禁止加载远程内容与执行远程脚本；外部链接交给系统浏览器；除用户自选数据源与模型调用外，不向外发送用户数据与凭证。
- **验收规则**：
  - [ ] AC-009-1 本地服务端口仅绑定 127.0.0.1（外部机器无法连接）
  - [ ] AC-009-2 渲染层配置拒绝远程内容（含远程脚本/iframe），尝试加载远程资源被阻止
  - [ ] AC-009-3 打开外部链接时不在应用内导航，而是交给系统浏览器
  - [ ] AC-009-4 诊断包与日志中不含凭证、档案邮箱与用户文档内容（阳性样例验证）

### R-010 日志与诊断

- **what**：应用在用户数据目录内写滚动日志（含后端与外壳），用户可一键导出脱敏诊断包（版本、环境、最近日志、进程状态）。崩溃时保留现场。
- **验收规则**：
  - [ ] AC-010-1 日志按大小/日期滚动，不无限增长
  - [ ] AC-010-2 一键导出诊断包，内容含版本与环境、最近日志，且已脱敏
  - [ ] AC-010-3 崩溃后重新启动，能读到上次崩溃的日志与原因

## 4. 约束与依赖

- **决策**：D-001（桌面应用）、D-007（桌面外壳 Electron + Python 子进程）、D-008（Vue 3 前端）、D-010（FastAPI 后端）、D-011/D-016（界面形态与双循环）
- **文档权威**：`docs/plan.md` §2/§6/§8（定位、分层、路线图）、`docs/interaction.md`（双循环与作业模型）、`docs/designUI.md`（界面形态）、`docs/architecture.md` §2（分层职责）
- **依赖 feature**：
  - `frontend-workbench`（前端壳/设计系统/工作台-作业-学习导航容器）——其构建产物是本 feature 的渲染内容
  - `settings`（档案/引导/开通向导核心）——本 feature 只做界面宿主（承担其 AC-002-1、AC-002-3 与 AC-003-3/AC-003-5 的界面子句）
  - `data-layer v23`（后端数据服务，含单写者锁与内部只读通道）
  - `api`、`agent` 相关 feature 未就绪时，本 feature 以 mock 前端 + 后端现有能力验收（AC-002-4）
- **环境**：Windows 11 为主；基准机器与 1440×900 视口（沿用 `frontend-workbench` 基准）
- **数据目录**：默认 `%LOCALAPPDATA%/FuturesAI`（沿用 data-layer §3.3 布局），本 feature 不改变其内部结构
