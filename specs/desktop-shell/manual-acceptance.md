# desktop-shell 人工验收步骤（manual-acceptance.md）

> **性质**：Implement 完成后由人执行的真实 GUI / 安装 / 系统集成步骤，与 plan §9 的 M-ID 一一对应。
>
> - 本文件**不是**需求质量检查清单：Checklist 归审核员 A，见 `checklist.md`。
> - 本文件**不是** Implement 的前置条件。
> - 本文件里没有复选框；执行结果写进 `review.md` 的验收证据（模板见文末）。
>
> - **作者**：Plan = claude-opus-5-5 via anthropic。**基线**：`8ba1b6a`。按 plan 修订 3 对齐（日志目录 `log\`、事件夹具只接受文件路径、M-03 以实际安装目录为准、M-09 为真实聚焦的唯一证据）。
> - **环境标签**（每次记录必填）：
>   - `干净机`：无 Python/Node 的 Windows 11，含 Windows Sandbox；
>   - `过渡机`：已装开发运行时，Q-009 允许的过渡环境；
>   - `基准机`：spec §4 规定的基准机器。
> - **证据类别**：
>   - `真实`：真实后端与真实系统行为；
>   - `夹具`：使用 `FAI_TEST_HOOKS=1` 的事件或更新源夹具，窗口标题会带"［测试钩子］"。**夹具结果不得写成真实作业或真实发布通道已验证。**
> - **通用准备**：
>   - 安装版：运行 `packaging/build.ps1` 生成的 NSIS 包；
>   - 开发版：`cd shell && npm ci && npm start`。
>   - 需要夹具时，在同一个终端先设置环境变量再启动。
>   - **事件夹具协议（唯一格式）**：`FAI_TEST_EVENTS` 只接受一个 UTF-8 JSON 文件的**绝对路径**，文件内容是事件数组；每项的 `delayMs` 相对"首次后端就绪"计时（不累加）。文件缺失或内容非法时应用以退出码 4 退出并输出 `TEST_EVENTS_INVALID`——这本身说明夹具写错了，不是产品缺陷。

## 安装与启动

**M-01 干净机安装并启动（AC-001-1）**　环境：干净机（优先），没有则用过渡机并标注　证据：真实

1. 把安装包和 `SHA256SUMS.txt` 拷到目标机，先执行 M-25 核对哈希。
2. 双击安装包，按默认选项完成安装（未签名时 SmartScreen 会警告，记下是否出现）。
3. 从开始菜单启动 FuturesAI。

期望：出现启动页，随后进入引导页；全程不要求安装 Python/Node，也不需要命令行。
记录：安装路径、是否有 SmartScreen 警告、截图。

**M-02 冷启动计时与无白屏（AC-001-2、AC-002-1）**　环境：基准机（判定）；其他机器只记参考值　证据：真实

1. 重启机器，登录后等待 1 分钟。
2. 启动应用，同时开始计时。
3. 观察首帧：应为深色启动页，显示"正在启动"一类的状态文字，不是白屏。
4. 退出后打开 `%LOCALAPPDATA%\FuturesAI\log\shell.log`，找到 `startup_timing`。

期望：首帧不是白屏；在基准机上 `interactive_ms` ≤ 15000。

**M-03 卸载残留（AC-001-3）**　环境：M-01 的机器　证据：真实

1. 正常使用一次（完成引导），然后退出。
2. **卸载前**确定实际安装目录 `<INSTDIR>`：以 M-01 记录的安装向导所选目录为准（安装允许改目录，默认是 `%LOCALAPPDATA%\Programs\FuturesAI`），并用 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\` 下本应用条目的 `UninstallString` 所在目录核对。不得只检查默认路径。
3. 通过"设置 → 应用 → 安装的应用"卸载 FuturesAI。
4. 检查以下目录：
   - `<INSTDIR>`
   - `%LOCALAPPDATA%\FuturesAI-Shell\session`
   - `%LOCALAPPDATA%\FuturesAI-Shell\run`
   - `%LOCALAPPDATA%\FuturesAI`
   - `%LOCALAPPDATA%\FuturesAI-Shell\shell-prefs.json`

期望：前三项不存在；`%LOCALAPPDATA%\FuturesAI` 完整保留；`shell-prefs.json` 保留。
记录：实际 `<INSTDIR>`、核对来源（M-01 记录 / 注册表）。

**M-04 安装包内容抽查（AC-001-4）**　环境：构建机　证据：真实

1. 打开 `shell\dist\win-unpacked\resources`。
2. 抽查 `app\`、`backend\`、`app-config.json`。

期望：没有 `.duckdb`、`.sqlite`、`profile.bin`、`eia_api_key.bin`、`creds`、`host.json`、`.log`、`tests`、`.env`；`app-config.json` 中没有任何凭证。与 `scan-package.js` 的输出一致。

## 后台、托盘与通知

**M-05 关窗后作业继续，托盘显示运行中（AC-006-1）**　环境：安装版或开发版　证据：夹具（作业）+ 真实（托盘）

1. 准备事件文件，例如 `C:\fai-test\events.json`，内容：`[{"type":"job.started","jobId":"J1","title":"示例作业"}]`。
2. 设置 `FAI_TEST_HOOKS=1`、`FAI_TEST_EVENTS=C:\fai-test\events.json`（绝对路径），然后启动。
3. 确认标题带"［测试钩子］"。
4. 点击窗口关闭按钮。

期望：窗口隐藏，进程仍在；托盘图标或提示显示"运行中（1）"；托盘菜单"运行中作业"中列出"示例作业"。

**M-06 系统通知开与关（AC-006-2、AC-006-3）**　环境：**安装版**（Windows 通知依赖 AppUserModelID）　证据：夹具（事件）+ 真实（toast）

1. 准备事件文件：`[{"type":"job.started","jobId":"J1","title":"示例"},{"type":"job.stage_completed","jobId":"J1","stage":"数据提取","delayMs":5000}]`，按 M-05 的方式启动。
2. 约 5 秒后观察系统通知。
3. 到"设置 → 应用"关闭系统通知，退出后重新启动（同一个事件文件）。

期望：第 2 步出现"阶段完成"的系统通知；第 3 步不弹通知，但托盘状态照常变化。

**M-07 托盘菜单（AC-006-4）**　环境：同 M-05　证据：夹具 + 真实

依次使用托盘菜单的"打开主窗口""运行中作业""设置…""导出诊断""退出"。

期望：
- 窗口恢复并聚焦；
- 子菜单列出作业；
- 设置页打开；
- 资源管理器定位到诊断 ZIP；
- "退出"弹出运行中作业的提示（接 M-08）。

**M-08 退出提示：取消退出 / 等待完成（AC-003-2、AC-003-4）**　环境：同 M-05　证据：夹具

1. 事件文件内容：J1 的 `job.started`、J2 的 `job.queued`、J3 的 `job.queued`（`delayMs` 10000）、J1 的 `job.finished`（`delayMs` 20000）。第 3 步须在就绪后约 10 秒内完成，才能观察到 J3 被拒收。
2. 从托盘选"退出"，然后选"取消退出"。
3. 再次选"退出"，这次选"等待完成后退出"。

期望：
- 第 2 步应用继续运行，J1 仍在运行中；
- 第 3 步提示中列出 J2 将被标记为"退出时取消"，托盘显示"等待作业完成后退出"，J1 结束后应用自动退出；
- `log\shell.log` 中有 J2 `cancelled_on_exit` 与 J3 `rejected_exiting` 的记录。

## 单实例与数据目录

**M-09 双击第二次聚焦已有窗口（AC-004-1）**　证据：真实

1. 启动应用并等它就绪。
2. 再次双击桌面快捷方式。
3. 打开任务管理器，查看 `futuresai-backend.exe`。

期望：已有窗口被恢复并聚焦到前台；`futuresai-backend.exe` 只有一个。
说明：自动化 `single-instance` 只能证明处理器调用了 restore/show/focus 且后端未重复；Windows 前台锁下"窗口真正到前台"只以本步骤为证据。

**M-10 命令行写进程占用数据目录（AC-004-2）**　环境：过渡机（需要后端 CLI）　证据：真实

1. 应用处于退出状态。在终端执行 `cd backend && futureai-data --root "%LOCALAPPDATA%\FuturesAI" serve`，该命令持有写锁。
2. 启动应用。

期望：错误页说明"数据目录正被另一进程占用"并给出路径；提供重试、查看日志、导出诊断；不会反复自动重启。停止 serve 后点"重试"，应用能就绪。

**M-11 数据目录不可写（AC-004-3）**　证据：真实

1. 在"设置 → 应用 → 数据目录"中选一个新目录，然后对该目录执行 `icacls <目录> /deny %USERNAME%:(W)`；或者选一个写保护的 U 盘目录。
2. 点"立即重启"。

期望：错误页指出该路径和"权限不足/只读"等具体原因；不会静默改用临时目录；提供"继续使用原目录"。事后执行 `icacls <目录> /remove:d %USERNAME%` 恢复权限。

**M-12 更改数据目录（AC-004-4）**　证据：真实

1. 在原目录中记下一个文件，例如 `log\shell.log`。
2. 在设置中把数据目录改到新的空目录，点"立即重启"。

期望：应用在新目录就绪（因为新目录为空，会重新进入引导）；设置页显示新路径；原目录里的文件全部还在。

## 引导与设置（承载 settings 的界面子句）

**M-13 首启引导、跳过、补填（AC-005-1、AC-005-2）**　证据：真实

1. 用全新数据目录启动 → 进入引导 → 点"跳过"。
2. 重启 → 直接进入设置页。
3. 在设置页填写档案并保存。

期望：引导只出现一次；跳过后可以从设置页补填；托盘或菜单的"设置…"始终能打开设置页。

**M-14 EIA 开通真实走查（AC-005-3）**　环境：第 1～2 步离线即可；第 3～6 步联网，需要真实 EIA key【外部】　证据：真实

1. **缺项引导**：在设置页把档案的姓、邮箱或组织类型清空并保存，点"准备注册信息"。
2. **完整预填**：补齐档案（含组织类型与使用原因）并保存，再点"准备注册信息"。
3. 点"在浏览器打开 EIA 注册页"（系统浏览器打开），按逐项指引手工填写；程序不代提交。
4. 粘贴一个错误 key → 点"验证并保存"。
5. 粘贴真实 key → 点"验证并保存"。
6. 点"清除已保存的 key"。

期望：
- 第 1 步列出缺项与"先补齐档案"的提示，页面上没有"打开注册页"；key 粘贴与"验证并保存"仍可用（已有 key 的用户不必重新注册）；
- 第 2 步逐项指引显示 First Name、Last Name、Email（档案真实值，仅因你点击而显示）、Category（官方英文标签，不是内部代号）、Reason for use，与档案一致；
- 错误 key 给出可操作原因，且没有被保存；
- 真实 key 验证成功，状态表中 eia 变为 API；
- 清除后提示"当前回到免凭证回退路径"。

没有真实 key 时只执行第 1、2、4 步，并记为"部分执行"。

**M-15 凭证与邮箱不明文显示（AC-005-4）**　证据：真实

1. 在 M-14 中观察输入框，内容应为遮蔽显示；验证成功后输入框被清空。
2. 在设置页把档案邮箱设为真实邮箱，保存后刷新：**普通档案区**只显示遮蔽形式；不改邮箱、只改姓名再保存后，真实邮箱没有被覆盖（点"准备注册信息"，在注册指引中核对 Email 仍为原值）。
3. 确认注册指引只在点击"准备注册信息"后出现，离开设置页再回来时已清空。
4. 用 Ctrl+F 在 `log\*.log` 中搜索 key 和完整邮箱（包括第 2 步在注册指引中显示过的邮箱）。

期望：第 2、3 步如上；第 4 步都搜不到。说明：注册指引中显示档案邮箱是用户为手工填写第三方表单而显式请求的本地指引，邮箱不是 API 凭证；日志与诊断包中仍不得出现邮箱（AC-009-4）。

## 故障与恢复

**M-16 后端崩溃自动重启与上限（AC-002-3）**　证据：真实

1. 应用就绪后，在任务管理器中结束 `futuresai-backend.exe`。
2. 观察到"重启中"后又就绪。
3. 连续再结束 3 次，每次都等它重新起来后再结束。

期望：
- 前 3 次都自动恢复，托盘短暂显示错误态（通知开启时会收到"后端异常"）；
- 第 4 次后出现"后端连续异常退出"错误页，带"导出诊断"。

**M-17 前端资源缺失（AC-007-3）**　环境：拷贝出来的 `win-unpacked` 目录　证据：真实

1. 在拷贝的目录中把 `resources\app\renderer\onboarding.html` 改名（builtin 构建）；或者删除 `resources\frontend\index.html`（bundled 构建）。
2. 运行拷贝目录里的 exe。

期望：显示可操作的错误页（`frontend_missing`，"界面资源缺失或加载失败"，含重试、打开日志），不是白屏。

**M-18 磁盘写满（AC-007-4，可选）**　环境：管理员权限　证据：真实

1. 用 `diskpart` 创建一个 64 MB 的 VHD，挂载为 X: 后格式化。
2. 把数据目录改到 `X:\FuturesAI` 并重启。
3. 用 `fsutil file createnew X:\fill.bin <剩余字节数>` 占满空间。
4. 在设置页保存档案；导出诊断。

期望：界面提示"磁盘空间不足"，应用不崩溃，删除 `fill.bin` 后可以继续使用。

## 安全与诊断

**M-22 外链交给系统浏览器（AC-009-3）**　证据：真实

点"在浏览器打开 EIA 注册页"。

期望：系统默认浏览器打开该页面；应用窗口内容不变。

**M-23 诊断包导出与内容核查（AC-010-2、AC-009-4）**　证据：真实

1. 完成 M-13～M-15 之后，在设置或托盘中点"导出诊断"。
2. 解压 ZIP，逐个打开其中的文件。

期望：
- 只有 `manifest.json`、`env.json`、`process.json`、`log/…`，以及（如有）`crash/last-crash.json`；

- 搜索 key、完整邮箱、文档内容、用户名路径，都没有命中。

**M-24 崩溃后读取上次原因（AC-010-3）**　证据：真实

1. 应用就绪后，在任务管理器中结束 `FuturesAI.exe` 的主进程。
2. 确认 `futuresai-backend.exe` 在几秒内也自行退出。
3. 重新启动，打开"设置 → 诊断"。

期望：应用正常就绪（AC-003-3）；诊断区显示"上次异常退出"的时间与原因，可以打开日志查看。

**M-25 安装包完整性校验（R-008 what / WO-08）**　证据：真实

在 PowerShell 中执行 `Get-FileHash <安装包> -Algorithm SHA256`，与 `SHA256SUMS.txt` 比对。

期望：一致。

**M-26 外部机器无法连接与出站核查（AC-009-1、WO-10，可选）**　环境：同一局域网的第二台机器，或网络监视工具　证据：真实

1. 用 `netstat -ano | findstr <后端 pid>` 查到监听端口，然后从第二台机器执行 `Test-NetConnection <本机 IP> -Port <端口>`。
2. 可选：用资源监视器的"网络"页观察应用进程的出站连接。

期望：第 1 步连接失败；第 2 步只看到用户触发的数据源请求和已配置的更新源请求，没有其他出站连接。
