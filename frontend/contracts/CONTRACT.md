## 1. 通用约定

- **version**：1.0.0
- **validation**：mock / real 实现仅在输入与输出边界 parse 一次；界面消费确定类型，不重复校验。
- **errorDelivery**：所有请求方法失败时以 {error:{code,message,retryable}} 拒绝 Promise；已开始运行的失败通过 run.failed 发布。
- **pagination**：v1 所有列表一次返回，不分页；空列表不等同于请求失败。
- **date**：date、from、to 为交易日 YYYY-MM-DD；日历区间包含两端，按发布时间升序返回。
- **timestamp**：asOf、ts 必须为 ISO 8601 带偏移时间，Z 为 UTC；不接收无时区本地时间。
- **delta**：deltaKind=pct 时 delta 是百分数值，例如 1.5 表示 1.5%，不是 0.015。
- **events**：每个事件携带 runId、sessionId、ts；stepId 在 run 内单调，同一步文本允许复用编号；done=false 追加，done=true 用权威全文替换；每个 run 恰好一个终态。

### 错误形态

`{error:{code,message,retryable}}`；成功结果不包裹 `error`。
错误码：`not_found` / `validation_error` / `rate_limited` / `adapter_error` / `internal`。
数据方法与 send 以此形态拒绝 Promise；已受理的运行以 `run.failed.error` 传递相同错误详情。
未实现的 real 桩抛出 `NotImplementedError`，其 `error` 字段为相同详情（internal、不可重试）；subscribe 为同步抛出。

### `send`

提交用户消息并返回会话与运行 ID；缺省 sessionId 时创建会话，回执仅表示受理，运行进度由 subscribe 提供。

- 参数（位置参数元组）：`sendParams`
- 成功结果（Promise）：`SendReceipt`
- 拒绝：`ErrorResponse`

### `subscribe`

注册应用级事件监听，切页与收起抽屉不取消订阅；v1 不提供历史补发。

- 回调 `cb`：接收已在契约边界校验的 AgentEvent；应在发送消息前完成订阅。
- 事件：`AgentEvent`
- 返回 `() => void`：取消当前监听的函数；不结束 agent 运行，也不提供中止交互。

## 4. Mock 与实现选择

- 应用仅从 `src/contracts/index.ts` 导入 `dataClient` / `agentClient`。`VITE_DATA_MODE=mock|real`，缺省 mock；real 所有方法均为 NotImplementedError 桩，不发网络请求。
- 场景选择：`?scenario=` > `VITE_MOCK_SCENARIO` > `normal`。未知场景报 validation_error。每个 client 创建时固定场景，切换场景后重新加载应用。
- `normal`：返回内置样例；mock 当前交易日固定为 daily-brief fixture 的 date，不随机器时钟变化；指定其他交易日返回 brief=null 与原因。
- `empty`：目录仍为七个模块，日报为空并含原因；盘面 rows / points、关注列表、日历、摘要 text / figures、资讯、数据源和研究列表为空，数值元数据保留。
- `error`：bootstrap、getModuleCatalog、getNewsTicker、getSourceStatus、getResearchList 成功；getDailyBrief、getMarketBoard、getWatchlist、getReleaseCalendar、getModuleSummary 拒绝固定 adapter_error（可重试）。
- `slow`：每次数据请求与 send 受理延迟 1500ms；subscribe 立即注册，事件按脚本相对受理时间回放。
- `boot-error`：同一 DataClient 的 bootstrap 首次拒绝 internal（可重试），后续重试成功；其他方法正常。
- fixture 覆盖：`window.__FAI_MOCK__.fixtures`，键为 JSON 文件名（不含扩展名），值为完整替换，不做深合并；每次请求读取覆盖值，在契约边界校验。非法参数或 fixture 拒绝 validation_error；没有示例摘要的模块拒绝 not_found。
- fixture 键：`module-catalog`、`daily-brief`、`market-board`、`watchlist`、`release-calendar`、`module-summaries`、`news`、`sources`、`research`。module-summaries 是模块 ID 到 ModuleSummary 的映射。所有数据为合成样例，不含真实头寸、凭证或私有文档。

```js
window.__FAI_MOCK__ = {
  fixtures: { research: [{ id: 'demo-research', title: '新增研究（样例）' }] },
  agentScript: 'retry',
}
```

## 5. Agent 回放

- 脚本选择：`?agentScript=` > `window.__FAI_MOCK__.agentScript` > `success`；每次 send 选择，未知脚本拒绝 validation_error。
- 四份脚本：success（增量、权威全文、工具结果、模块 / 页面 / 未知目标导航、完成）；failure（工具错误、非终态 step.error、失败）；retry（限流后重试并完成）；long（12 秒、分批步骤、完成）。场景不替代脚本选择。
- 脚本格式 `[{afterMs,event}]`：afterMs 是相对消息受理的毫秒偏移，不是与上一事件的间隔。回放时替换 runId / sessionId / ts / prompt，生成新运行 ID；已有 sessionId 原样复用。
- send 的回执先于首个事件；应先 subscribe。取消监听不停止运行，不回补历史，也不重新开始脚本；应用级监听应跨页面与抽屉存续。
- 十种事件见字段清单；run.aborted 保留用于未来映射，无中止按钮或 abort 脚本。每份完整脚本在发出前经过一次 AgentRun 边界校验，只有一个终态。
