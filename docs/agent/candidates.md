## 1. 使用边界

这里保留 brainstorm 的未决想法、依赖与已晋升映射；**候选不是决策、不是实施入口，也不是已承诺路线图**。状态 `candidate` 只表示待评估，不表示排期、批准或已实现。

晋升须按顺序走 **ADR → 权威 docs 同步 → feature spec / Clarify → Gate 1 → Plan / Checklist / Tasks / Analyze → Implement / Converge / 独立 Review → Gate 2 / Handoff**，不得从候选直接开工，也不得绕过 `AGENTS.md` §2。若仅细化已有决策，需明确沿用的 ADR；超出其边界须先登记新 ADR。功能实施的唯一入口仍是 `specs/<feature>/`。

**已决高层与候选细节分开**：D-022 已接受 A3 自扩展及沙箱、网络白名单、异模型审查与人批准（Phase 4）；D-021 已接受情景能力（Phase 2D）。下表只追踪其尚未冻结的规范细节或扩展，不把已批准能力重新降为未决。Phase 2C 已有 asof 复盘，研究回放候选是其增强，不替代既有范围。阶段与分期权威为 `../plan.md` §8，交互权威为 `../interaction.md`。
