# Futures-AI 交互架构（interaction.md）

> 人与 agent 如何在同一工作台上协作：双循环模型、作业与四阶段契约、介入机制、交付物与验证性需求、知识回流规则、学习循环与分析协议。
> 权威分工：本文是**交互与协作模型**的权威；系统落点见 `architecture.md`，界面语言与组件见 `designUI.md`，方案与路线图见 `plan.md`。
> 建立 2026-10-28（D-016、D-017）。变更本文即变更产品交互方案，须先登记 ADR 并同步三份文档。

## 1. 定位与设计命题

### 1.1 从"AI 分析软件"到"Agent+人 双循环工作台"

旧定位隐含两个假设：主导对象是"日报/图表"，循环是单向的（数据 → 分析 → 交付即结束）。后果是人的介入无处安放、交付物不是下一轮研究的起点、人的修改无法沉淀。

新定位：**以"作业"为单位的人机共同交付 + 交付物反哺问题 + 与交付共享底座的认知学习。**

- 人的角色是**补充者与共同作者**，不是审批者：人提供意图、来源语境、业务口径、分析框架与判断标准、取舍与发布决策（§3.1）。
- 对话不是产品主体，只是众多接口之一；主体是作业与产物（§2.4、`designUI.md` §3）。

### 1.2 三类市场产品的错配

| 类型 | 代表形态 | 缺什么 |
|---|---|---|
| 对话优先型 | 通用助手、Perplexity 类 | 产物是附件；数据阶段、改稿阶段没有结构化介入面 |
| 副驾型 | Office / 编程 Copilot | 人只提要求与验收；编辑轨迹不沉淀为可复用规则 |
| 检索终端型 | AlphaSense、行情终端 | 有数据与检索，没有"交付—反馈—再采集"闭环，也没有学习线 |

共同缺失三件事：**人的介入不是一等数据、交付物不是下一轮问题的生成器、知识回流没有闸门**。

### 1.3 五条第一性原理

1. **人是补充，不是审批**：只有人能提供意图、来源语境、业务口径、分析框架与判断标准、最终取舍；这些是 agent 无法从数据中推导的输入。
2. **介入是一等数据**：每次介入都是可回链的结构化事件，既是协作输入，也是学习原料（§3.4、§6）。
3. **交付物是下一轮问题的生成器**：交付完成即抽取"验证性需求"，用户确认后生成新作业（§3.6）。
4. **知识回流必须有闸门**：溯源、去重、派生隔离缺一不可，否则自迭代会退化为自引用污染（§5）。
5. **学习与交付共享底座但形态不同**：学习由用户发起、信息密集、无固定交付模板，以"认知增量"衡量（§4）。

## 2. 概念模型

### 2.1 五个对象

| 对象 | 定义 | 边界 |
|---|---|---|
| **作业 Work** | 一次交付任务的容器：日报、专题、临时问题、验证追踪 | 有阶段、版本、参与者（人/agent）与状态机（§3.7） |
| **产物 Artifact** | 阶段产出：数据集与加工配方、分析稿、交付文档、学习笔记 | 版本化；人改与 agent 改都生成新 revision |
| **介入 Intervention** | 人在任意阶段的结构化动作 | 事件化、可回链；不是覆盖写（§3.3–3.4） |
| **知识底座 Knowledge** | 源材料 / 断言 / 派生视图 + 谱系 | 分可信区与派生区；写入必须过闸门（§5） |
| **分析协议（playbook）** | 从介入中学到的框架、判断标准、表达与数据偏好 | 显式、可编辑、可版本回退（§6） |

### 2.2 两条循环与共享底座

```
                ┌──────────── 共享底座 ────────────┐
                │ 数据/知识库（带谱系） + 分析协议     │
                └───────┬───────────────▲──────────┘
                        │               │
        ┌───────────────┘               └────────────────┐
        ▼                                                │
  ① 交付循环（agent 主跑，人补充）                    ② 学习循环（用户发起，信息密集）
  提取 → 处理 → 分析 → 交付物                          阅读 / 复盘 / 深挖 / 自测
    ▲                    │                                    │
    └── 验证性需求 ←──── 交付物 ─────── 复盘、延展阅读 ─────────┘
        （agent 提取 + 人确认）        （交付物同时是学习材料）
```

- **交付循环**由 agent 主跑、人补充，四阶段见 §3.2；每次交付的产物进入共享底座。
- **学习循环**由用户发起（§4），产物（笔记/框架/问题）回流底座与协议。
- 两个方向的互相喂养：交付物是学习材料；学习产物与验证性需求又回流为断言、协议候选或新作业。

### 2.3 三层自迭代

| 层 | 机制 | 回答的问题 | 验收指标 |
|---|---|---|---|
| L1 产物迭代 | 版本、diff、局部重跑 | 这一次能否改到满意 | 人改率、返工轮次 |
| L2 协议迭代 | 介入痕迹 → 分析协议 | 下一次能否更接近人的判断 | 一次通过率、追问密度 |
| L3 知识迭代 | 写入闸门 + 断言台账 + 验证性需求 | 底座是否越来越厚、问题越来越准 | 断言溯源覆盖率、冲突解决时长 |

### 2.4 主导对象与边界

- **作业**是交付侧的主导对象；**模块工作台**（`designUI.md` §3）是常驻监测面（行情、指标、日历），两者不互相替代：模块负责"看"，作业负责"做"。
- **日报**不再是一条独立管线，而是"定时作业"的一种交付物模板（`architecture.md` §6）。
- **对话**保留（时间线、后台运行、角标等能力仍是资产），定位为"自由指令与解释"的接口；结构化介入优先走阶段界面。

## 3. 交付循环

### 3.1 人的五类补充输入

| 只有人能提供 | 对应阶段 | 落成什么 |
|---|---|---|
| 意图与优先级（为什么做、关注什么） | 作业创建 | 作业 / 研究议程 |
| 来源语境（这份材料可信吗、用来干什么） | 数据提取 | 来源说明 + 可信度标签 |
| 业务口径与常识（计算规则、口径选择） | 数据处理 | 加工配方参数 |
| 分析框架与判断标准（怎么看、什么算证据） | 分析 / 交付 | 介入事件 → 分析协议 |
| 取舍与责任（发不发、怎么改、改到什么程度） | 交付物 | 批准 / 发布决策 |

### 3.2 阶段契约

| 阶段 | Agent 自动做 | 人的介入（动词） | 界面 | 检查点 |
|---|---|---|---|---|
| **提取数据** | 适配器取数、文档解析、网页/粘贴抽取、表格识别、标准化（时序 / 表 / 断言） | 投放文件/链接/粘贴文本；写来源说明（用途·可靠性·时效·口径）；修正抽取映射；标"存疑/仅供假设"；拒绝来源 | 采集台（全局 + 作业内） | 溯源完整性 + 去重闸门；未过闸入"待补证区" |
| **数据处理** | 清洗、单位/时区/日历对齐、重采样、派生指标、对账、表卡 | 指定口径与加工规则、否决错误合并、补计算逻辑/Excel 稿、标注修订 | 处理台（配方 DAG + 对账 diff） | 配方可解释；每个派生值可回溯到源观测 |
| **分析延申** | 按分析协议 + 数据生成结论、证据链、图表，主动提反证 | 注入框架/观点、追问"依据/如果…"、删减、要求深挖、否决结论 | 分析台（结论卡 + 证据链 + 批注/追问） | 每条结论必须有证据锚；无锚标"推断" |
| **交付物** | 组装块式文档/图表/引用、生成发布快照、导出 | 行内编辑、块级批注、指挥 agent 改稿、批准发布 | 交付台（块编辑器 + 版本 + diff） | 发布快照；发布后自动抽取验证性需求 |

补充规则：

- 每个阶段以**产物**交接，不以对话交接；交接即生成 revision 与检查点。
- "自动"不意味着不可介入：人的任何介入都合法，只是不阻塞 agent（§3.3）。
- 阶段可因数据不足/冲突停在"待人工确认"；下游仍可用**暂定**产物继续推进，不必等待。

### 3.3 介入而不干扰（R1–R6）

1. **一切产物版本化**：编辑不覆盖，产生 revision（base + diff + 作者 + 谱系），可回看、可回滚。
2. **人的介入走旁路**：agent 不被打断，继续在最新已合并快照上工作；人的改稿进入 overlay 层，检查点合并。
3. **下游用最新版本继续**：冲突**不阻塞**流程，只在发布检查点要求处理；任何时刻可显式"重跑本阶段及下游"，不重跑上游。
4. **无模态确认**：只有破坏性动作（删源、发布、外发、清库）要确认；其余不弹窗、不审批。
5. **状态与来源可见**：每个块/数字/结论带**来源徽**（外部源 / 人 / agent / 混合）与**状态徽**（草稿 / 暂定 / 已确认 / 冲突），不让人猜哪部分是 AI 写的。
6. **通知节制**：用角标和收件箱，不弹窗打断。

实现含义：上述六条要求作业引擎（`architecture.md` §5.4）提供"阶段状态机 + 产物版本 + 检查点合并 + 介入事件"四项能力；不得用"等待用户确认才继续"的实现替代旁路。

### 3.4 介入事件

```
intervention { id, work_id, stage, artifact_id, base_rev, kind,
               payload(diff / note / framework), reason, outcome, created_at }
```

字段为示意，最终 schema 以 workflow feature spec 为准。`kind` 不是 UI 埋点，而是**学习分流器**：

| kind | 例子 | 去向 |
|---|---|---|
| `ingest` | 投放材料、写来源说明 | 知识底座（过闸门） |
| `map_fix` / `recipe` | 修正列映射、指定口径 | 数据处理配方 |
| `framework` / `ask_why` | 注入分析框架、追问依据 | 分析协议候选（§6） |
| `delete` / `rewrite` / `veto` | 删减、重写、否决结论 | 分析协议候选 + 产物修订 |
| `approve` / `pin_rule` | 批准发布、显式"记住这条" | 发布快照 / 协议强规则 |

### 3.5 交付物：块模型、版本与发布

- **块模型**：权威定义在 `designUI.md` §5.2（块类型、状态、锚）。
- **版本**：编辑产生 revision（base + diff + 作者 + 谱系）；发布 = 不可变快照。
- **发布门**：默认由人确认；是否支持"草稿自动发布"由交付/工作流 feature spec 决定（D-016 未裁定）。
- **溯源**：每个数字/结论可追到断言或观测（`architecture.md` §6）；来源徽常驻。
- **改稿**：人可对块批注、直接编辑或下指令；agent 改稿产出新 revision 并给出 diff，人可接受/回退。

### 3.6 验证性需求 → 新循环

交付完成后由 agent 抽取四类需求：

| 类型 | 含义 | 采集计划例 |
|---|---|---|
| 延展采集 | 补更长历史、更多地区/品种/维度 | 主动：一次性深挖并入库 |
| 证据追踪 | 跟踪某数据/公告/报告的后续变化 | 定时：按发布节奏周期采集 |
| 假设验证 | 给"若…则…"的观察条件与触发阈值 | 事件：触发条件满足时采集/提醒 |
| 反证搜索 | 主动找与结论相反的证据 | 主动 + 定时 |

每张验证卡带：问题、为什么现在问（回链交付物块）、期望来源、时效/节奏、优先级。**用户确认闸门**：接受 → 生成新作业（继承父作业与已有产物）→ 回到提取阶段；拒绝/稍后 → 留在验证队列。

监测到变化 → 通知 + 生成**增量版本**（不整篇重写）。验证队列与"数据发布日历"模块天然衔接。

### 3.7 作业与产物状态

- 作业状态：`draft → collecting → processing → analyzing → delivering → delivered`，可进入 `verifying`；旁路状态 `paused / needs_human / blocked / failed / cancelled`。
- 产物状态：`draft / provisional / confirmed / conflict`（界面语义：`designUI.md` §2.4）。
- "待人工确认"不阻塞后续阶段（R3）；状态枚举以 workflow feature spec 为准。

## 4. 学习循环

### 4.1 定位与触发

学习区是**用户发起**的第二工作区，服务于缺少新数据/新观点时的复盘与认知强化。触发方式：

- 用户主动进入学习区、选择主题或材料；
- agent 在作业收尾/焦点带提议"是否复盘/深入"；
- 知识缺口图驱动的延展阅读建议（§4.3）。

### 4.2 学习会话结构

1. **主题与目标**：用户选题，或从交付物"深入此主题"。
2. **材料**：知识库检索 + 延展阅读建议（标注来源与可信度；外网检索按隐私开关）。
3. **陪读**：解释、术语、机制、类比、反例。
4. **自测/复盘**：主动回忆、错题、可选间隔重复。
5. **发散**：多角度、跨品种、历史对照。
6. **产物**：笔记、概念图/大纲、学习日志、待验证问题、认知缺口清单。

### 4.3 学习产物与回流

- 笔记/框架 → 派生区（`origin=derived` + 学习会话谱系，§5）。
- 新问题 → 验证队列（§3.6）。
- 框架候选 → 分析协议（§6）。
- 认知缺口 → 延展阅读与采集建议。

### 4.4 与交付循环的差异

| 维度 | 交付循环 | 学习循环 |
|---|---|---|
| 主导 | agent 主跑，人补充 | 人主导节奏，agent 陪读/出题/串联 |
| 产物 | 交付物（可发布） | 认知产物（笔记/概念图/问题） |
| 信息密度 | 结论优先、证据收敛 | 信息密集、多源并置、引用优先 |
| 质量判据 | 一次通过率、人改率 | 缺口闭合、认知产物被后续作业引用 |

### 4.5 界面原则

阅读器优先、双栏并置、引用常驻；无固定交付模板；视觉令牌与工作区一致但布局更"文档优先"（`designUI.md` §3.7）。

## 5. 知识回流与自迭代（D-017）

### 5.1 三类内容、三种入口

| 内容 | 例子 | 处理 |
|---|---|---|
| **源材料** | 用户投放的 PDF、网页、公告，外部抓取的数据 | 原件不可变；只做指纹去重防重复解析；保留完整谱系 |
| **断言** | "某地库存 10 月 27 日为 X 吨" | 进入**断言台账**（去重单位）；可被人/agent 生产，须回链来源 |
| **派生内容** | 分析结论、观点、笔记、图表摘要 | 进入**派生区**（`origin=derived`），带推导 DAG；不进入"独立证据"计数 |

"派生区"是逻辑分区（`origin=derived`），不要求独立物理目录；文本落点见 `architecture.md` §4.4。

### 5.2 写入闸门 L0–L5

| 层 | 做什么 | 命中/失败后 |
|---|---|---|
| **L0 溯源闸门** | 每条内容回答：来源、定位（页/块/行）、时间（发布/抓取）、作者类型（外部/人/agent） | 缺项 → 隔离区，不参与自动分析引用 |
| **L1 原文指纹** | 原始字节 sha256 + 规范化文本 sha256 | 重复上传只更新 `last_seen` |
| **L2 块级近重** | SimHash/MinHash + bge-m3 余弦；同文多来源 → 互证计数 | 近重不新增块，挂到已有块 `sources[]` |
| **L3 断言归并** | 抽取 {主谓宾/值, 期, 地区, 单位, 口径, 极性} → 归一化 → canonical key 精确匹配 + embedding 候选 + 判定 | 同断言同值 → 加证；同槽位异值 → claim revision + 冲突；新断言 → 插入 |
| **L4 派生隔离** | 派生内容带 DAG、`origin` 标记；不进入独立证据计数 | 只能作为"我们的分析"被引用；晋升需人工确认或独立外部源互证 |
| **L5 检索期去重** | 检索末端执行（MMR/断言聚类 + 派生降权） | 规则与展示见 §5.6 |

### 5.3 六种判定（"库里已有的不放"的可执行版本）

| 情况 | 是否新增 | 处理 |
|---|---|---|
| 同一文档重复上传 | 否 | 更新 `last_seen` |
| 同一事实、不同来源 | **不新增断言** | 给已有断言加**证据边**（互证 +1）——简单"不放"会丢掉最有价值的多源互证信号 |
| 同一事实、不同数值 | 不覆盖 | 新增 claim revision + 冲突标记（期货数据修订是常态） |
| 同一结论、不同证据/推理 | 是（新派生） | 独立派生保留，建 derived-from 边；证据源相同则降权 |
| 相同内容的派生重复 | 否 | 证据集合指纹 + 结论签名相同 → 复用旧派生、更新时间 |
| 无溯源/噪声 | 不进可信区 | 隔离区，可人工补证后再入 |

**去重语义 = 归并 + 加边**，不是丢弃。工程约束：幂等（同样内容重复跑结果一致）、可重算、每次判定留日志（why merged/rejected）、**人工可推翻**（"这不是同一件事"→ 拆分并反馈到规则/阈值）。

### 5.4 防自引用（红线）

如果 agent 自己的输出回流后又被当作"外部证据"检索回来，就会出现**回音室**：自我复读 → 看起来多源互证 → 置信度虚高。必须：

- 派生内容 `origin=derived`，检索与 prompt 中显式标注"内部结论，非外部证据"；
- 派生断言不得计入独立证据数；
- **晋升门**：只有人工确认或独立外部源互证，才能把派生断言升为"已确认断言"（晋升留痕）。

### 5.5 冲突、修订与晋升

- 同槽位异值不覆盖，生成 `conflict`，进入冲突队列；下游可用"暂定"值继续（R3）。
- 修订保留 vintages（与 `architecture.md` §3.4 的时序修订语义一致：修订即新版本）。
- 派生晋升、冲突裁定、合并/拆分决定均留痕，可回看；人工推翻记录进入规则/阈值调优。

### 5.6 检索期去重

检索管线末端执行 MMR/断言聚类（`architecture.md` §4.2）；派生内容标注并降权，不与外部证据混排；同一断言的多个来源以"N 个来源支持"展示，而不是重复列出。

### 5.7 成本分级与 v1 裁剪

- 外部文档：只做 L0–L2（每天数百页，不做全量断言抽取）。
- 人 + agent 产物与交付结论：做 L3–L4（每天量级小）。
- v1 先落 L0–L2 + 派生标记；L3 断言台账在知识库 v1 之后接入（`plan.md` §8）。

## 6. 从介入中学习：分析协议

### 6.1 介入类型 → 学习内容

| 介入 | 学成什么 |
|---|---|
| 事实更正 | 断言修正 + 数据/来源偏好 |
| "来源呢？"类追问 | 判断标准：无源不下结论（可强制） |
| 注入框架/观点 | 分析框架条目 |
| 质疑"为什么/如果…" | 推理链要求、反证习惯 |
| 删减/重写 | 表达与结构偏好 |
| 否决/接受 | 判断阈值 |
| 范围调整 | 关注范围/研究议程 |

### 6.2 蒸馏流程与门槛

- 触发：作业收尾、每周整合、用户手动"总结最近习惯"。
- 候选规则 `{类型, 陈述, 作用域（品种/阶段/交付物类型）, 证据（介入 id）, 置信度}`。
- 门槛：复发 ≥2 次，或用户显式教导（`pin_rule`）；单次改稿不升级为全局规则；与既有规则冲突交用户裁决。

### 6.3 生命周期与透明页

- 状态：`proposed → active → retired`；版本化，可回退。
- 生效方式：注入分析上下文；输出显示"本次应用 N 条规则"可展开。
- **透明页**（"Agent 学到的"）：每条规则可看证据、置信、作用域，可编辑/停用/删除。
- 显式教导优先：用户说"以后都这样"直接 `pin_rule`，不经复发门槛。

### 6.4 自迭代指标（"越用越懂用户"的可验收定义）

| 指标 | 含义 | 期望方向 |
|---|---|---|
| 交付一次通过率 | 首次交付后未要求重做的作业比例 | ↑ |
| 人改率 | 每份交付物的块编辑数/总块数 | ↓ |
| 返工轮次 | 同一作业的交付重做次数 | ↓ |
| 追问密度 | 每份交付物的"为什么/依据"追问数 | ↓ |
| 交付周期 | 作业从创建到发布 | ↓ |
| 断言溯源覆盖率 | 可回链来源的断言比例 | ↑ |
| 冲突解决时长 | 冲突从产生到裁定 | ↓ |

### 6.5 过拟合防护

- 单次干预不升级为全局规则；时间衰减 + 周期整合。
- 规则可停用/回退；协议变更留痕。
- 用户显式教导与隐式学习分开登记，前者优先。

## 8. 落地边界

### 8.1 非目标（v1）

- 完整自由的块编辑器（v1 只做轻量块模型 + 批注 + 版本/diff/发布）。
- 外部文档全量断言抽取（成本与噪声不可接受，见 §5.7）。
- 无审核的自动学习（协议候选必须经透明页；显式教导除外）。
- 跨用户共享分析协议（后续商业化评估）。

阶段划分、排序原则与依赖见 `plan.md` §8；指标定义见本文 §6.4。
