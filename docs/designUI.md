# Futures-AI 全局设计理念（designUI.md）

> 设计语言的权威入口。规范细节（数值、规则）以 `design/` 移植资产为准；本文定义理念、界面形态与暗色玻璃体系的组织方式。
> 界面形态部分源于产品视觉工作流（2026-10-26，见 D-011）；2026-10-28 按 D-016 扩展双区结构、作业轨道、介入界面与交付物块模型。交互模型权威见 `interaction.md`。

## 1. 设计原则

1. **数据第一**：界面是数据的载体，装饰不抢数据；每个数字可追溯出处
2. **克制**：颜色不刺眼、最大色块不抢戏、整份报告统一（源自 FTEngine 配色定版要求）
3. **暗色玻璃**：近黑暖灰底 + 玻璃层级——黑白灰阶体系 + 高质感玻璃，professional 风格
4. **中国色 DNA**：配色出自《中国传统色：故宫里的色彩美学》，核心体系「墨 + 黛驼」的暗色适配版
5. **品种无关的设计语言 + 品种定制内容**：底座 UI 与图表语法跨品种统一，油品内容在语言之上定制
6. **对象优先于对话**：界面主体是作业与产物，对话是接口之一（D-016）
7. **旁路介入**：人的介入不打断 agent，不弹阻塞式确认
8. **一切可回看**：版本、diff、来源徽与状态徽常驻，不隐藏 AI 生成与人工修改的痕迹
9. **双区**：工作区与格物致知区共享视觉令牌，但布局与信息密度不同
10. **状态透明**：草稿 / 暂定 / 已确认 / 冲突必须显式可见；派生内容另用来源标记，不让人猜
11. **介入可见**：定稿、复核、角色与成本都是界面元素——谁（人 / 哪个角色）在哪一步做了什么、花了多少，可回看（D-018 / D-019）

## 2. 配色系统（暗色适配版，基底移植自 FTEngine PALETTE_CORE，2026-10-02 定版）

### 2.1 界面色令牌（暗色玻璃）

| 令牌 | 值 | 用途 |
|---|---|---|
| 背景 | 渐变 `#1b1c1f → #121315 → #0f1012` | 全局底（近黑暖灰，非纯黑） |
| 玻璃面 | `rgba(255,255,255,.035–.06)` + blur 18px | 模块 / 焦点带 / 侧栏表面 |
| 玻璃边 | `rgba(255,255,255,.07–.12)`（D-011 结论 5 写 7–14%，此处取其子范围） | 层级描边 |
| 文字主 | `#e8e6e0` | 主文字、主序列线 |
| 文字次 | `#9a9892` / `#8f8d87` | 次级文字、占位 |
| 抽屉面 | `rgba(24,25,28,.82)` + blur 28px | 底部对话抽屉 |

玻璃层级限制**三层**：焦点带 / 模块 / 抽屉，防层级失控。

### 2.2 涨跌颜色（登记的行情语义位置专属，D-011 / D-015）

- 涨 = 茹藘红亮化 **`#C98A8F`**；跌 = 缥碧亮化 **`#8FB8A4`**
- 分析图表（供需/平衡表等）保持 FTEngine 语义：**红 = 负/减**；两套语义以模块 / 区块为界，互不渗透
- 作用域（D-015）：涨跌专色只用于登记的行情语义位置——行情价格模块、关注列表、今日焦点带"行情"段；焦点带分"行情 | 指标"两段，指标段沿用分析语义；状态色不用绿色；新增位置先新增一份后继 ADR（取代 D-015 的位置清单）并同步本节

### 2.3 图表色（暗色适配，随 design/charts 移植定稿）

- 主序列线：墨 → 亮化 `#E8E6E0`；多序列排位沿用黛驼体系亮化版
- 区间带（霜地）/ 均值（绍衣）/ 模型线（齐紫）：暗色亮化对应
- 退役色仍禁用（朱/骐驎/群青/石绿/茈藐）
- 导出/打印日报需同步提供**亮色纸底主题映射**（浅色版图表令牌）

### 2.4 状态与来源语义（界面登记）

状态/来源可见原则见 `interaction.md` §3.3（R5）；本节定义界面语义：

- 状态：草稿 / 暂定 / 已确认 / 冲突；状态徽不得只靠颜色区分（配文案或图标）
- 来源：外部源 / 人 / agent / 混合；来源徽与溯源入口常驻，不隐藏
- 派生标记：agent/人的分析产出额外标注"派生"（`origin=derived`），用于检索降权与防自引用（D-017）；引用派生内容时来源徽文案为"**内部生成**"并附根来源索引（可逐级点回外部源；根集合为空另标"推断"，D-018 §2）
- 状态色与具体色值随设计系统在实施阶段登记为令牌（不在本文先定值，防双份漂移）

## 3. 界面形态（D-011；2026-10-28 按 D-016 扩展）

### 3.1 双区结构

- **工作区**：工作台 · 作业 · 日报 · 价格 · 平衡表 · 物流 · 知识库 · 设置
- **格物致知**（第二工作区，D-018 §5）：阅读 · 复盘 · 深挖 · 笔记（区内二级导航；信息密集、阅读器优先；路由 `/learning` 不改）
- 左侧菜单固定 **9 项**：工作台 · 作业 · 日报 · 价格 · 平衡表 · 物流 · 格物致知 · 知识库 · 设置；"专题研究"作为作业类型保留，不再单列
- 知识库与设置两区共用；切换区时保持上下文
- 启动：加载页（可承载内容/通知）→ 跳转主页面工作台

### 3.2 工作台（工作区首页）

- 顶部今日焦点带：当日交付（通常为日报）的核心结论与数字，点击展开完整交付物（沿用 D-011）
- **作业轨道**（固定件，非模块、不可移除）：进行中作业的紧凑卡片，显示作业名/类型、四阶段进度、待介入角标、验证提醒；点击进入作业详情
- 模块栅格：模块库选择 + 固定栅格（不做自由拖拽）
  - 固定件：今日焦点带（顶部）、作业轨道、agent 输入栏（底部）
  - v1 模块库：行情价格 · 库存/供需指标 · 物流在途 · 当前头寸 · 文档目录 · 关注列表 · 数据发布日历
- 顶栏：新闻栏（资讯 ticker + 数据源状态）+ 全局"投放"入口（文件 / 链接 / 粘贴，进采集台）

### 3.3 作业详情（四阶段工作区）

- 顶部**阶段轨道**：提取 → 处理 → 分析 → 交付，每段显示状态（运行中 / 待人工确认 / 已完成 / 冲突）与介入角标
- 工作区随阶段切换：采集台 / 处理台 / 分析台 / 交付台；右侧常驻产物版本与介入历史
- 交付物入口常驻；阶段可被显式"重跑本阶段及下游"（保留历史）
- 待人工确认不阻塞 agent：下游继续用暂定产物推进（`interaction.md` §3.3）

### 3.4 介入界面

| 界面 | 解决什么 | 关键交互 |
|---|---|---|
| 采集台 | 人投放与来源语境 | 文件拖入 / 链接 / 粘贴；来源说明（用途·可靠性·时效·口径）；抽取预览与字段修正；**剪藏预览**（清理稿 vs 原始稿对照、frontmatter 可编辑、数字守恒校验结果，D-018 §3）；待归属池 |
| 处理台 | 数据口径与加工规则 | 配方 DAG 可视化、参数编辑、对账 diff、否决合并；从任一数字 / 图点开溯源 → 换源 / 修正别名 / 手工修正值 / 禁用来源（`architecture.md` §3.6） |
| 分析台 | 框架与判断标准的注入 | 结论卡 + 证据链、批注与追问、轻量"教它一条规则"、要求深挖 |
| 交付台 | 改稿与定稿 | 块编辑器、块批注 → agent 改稿、复核结果、版本历史与 diff、**定稿**（二次确认；定稿后徽章"已定稿 vN · 时间"，草稿导出带"草稿"水印）/ 导出 |
| 验证队列 | 下一轮研究的决策 | 验证卡（继续 / 稍后 / 丢弃）、采集计划、监测状态、增量版本 |
| 格物致知 | 复盘与认知强化 | 主题与材料、阅读器、陪读 / 自测、复盘卡双栏（当时 / 现在）、笔记与概念图（§3.7） |
| Agent 学到的 | 协议与记忆透明 | 规则证据 / 置信 / 作用域、停用 / 编辑 / 回退（§3.8） |

### 3.5 介入交互规范（界面表现）

规则来源 `interaction.md` §3.3（介入而不干扰）；本节只定界面表现：

1. **旁路标记**：人的改稿先落 overlay，块上标"待合并"；agent 继续运行，不出现阻塞式弹窗
2. **徽与角标常驻**：来源徽（外部源 / 人 / agent / 混合）、状态徽（草稿 / 暂定 / 已确认 / 冲突）、模块 / 作业 / 阶段角标
3. **冲突芯片**：冲突以芯片聚合，点开看两版差异；不阻塞下游，定稿检查点集中处理
4. **破坏性确认**：仅删除、定稿、外发、清库等破坏性操作弹确认
5. **版本轨迹**：块 / 产物 / 交付物都有版本与 diff；"重跑"入口显式且保留历史
6. **收件箱**：介入提醒与验证提醒进角标 / 收件箱，不弹窗打断

### 3.6 对话的定位

- 底部输入栏与抽屉保留：CoT 时间线、每步可展开、后台运行、模块角标、引导跳转（D-011 能力不变）
- 全局输入栏 = 自由指令；作业内输入框带上下文（当前阶段 / 选中块）
- 对话产生的修改落成介入事件，可回链产物；结构化介入优先走阶段界面
- CoT 时间线每步带**角色芯片**（剪藏员 / 对账员 / 分析员 / 撰稿员 / 复核员…）与模型档；作业详情显示累计成本（D-019）

### 3.7 格物致知形态

- 信息密集、阅读器优先：材料双栏并置、引用常驻、长文优先于卡片
- 无固定交付模板；产物是笔记 / 概念图 / 问题清单
- 视觉令牌共享，但布局更"文档优先"，不套用工作台的模块栅格

### 3.8 Agent 学到的（协议与记忆透明页）

- 集中展示从介入痕迹蒸馏出的分析协议：规则陈述、证据（介入记录）、置信度、作用域（品种 / 阶段 / 交付物类型）
- 每条规则可停用 / 编辑 / 回退；与用户画像、关注点共用入口
- 只可核查、不留黑盒：协议变更留痕

### 3.9 状态与角标语义

- 作业 / 阶段角标扩展为三类：运行中 / 待人工确认 / 冲突（完成态不常驻角标）；模块角标沿用 D-011 并可与作业关联
- 状态徽与来源徽见 §2.4；玻璃层级仍为三层（焦点带 / 模块 / 抽屉），作业轨道与阶段轨道不新增玻璃层级

### 3.10 与 D-011 的关系

- **保留**：首页工作台 + 焦点带、模块库 + 固定栅格、底部抽屉对话、模块角标、暗色玻璃（D-011 结论 4–8 的原有语义保留，角标扩展见 §3.9）；涨跌颜色语义保留，作用域见 §2.2
- **变更**：左侧菜单由 8 项扩为 9 项（"专题研究"→"作业"，新增"格物致知"——D-016 原名"学习"，D-018 更名）；工作台新增作业轨道固定件；对话从"唯一 AI 入口"降为"接口之一"（视觉形态不变）

## 4. 图表系统

### 4.1 kind 枚举（14 种，完整定义随 design/charts 移植）

season-daily（日/周度年份叠线）· season-monthly（月度年份叠线）· season-phase（合约年相位）· line（非年份时间序列）· dual（双 y 轴）· bar（全正值柱）· hbar（横条排序）· bar-signed（正负柱）· stack（类目堆叠柱）· area（堆叠面积）· scatter-fit（散点+拟合）· band（区间带）· heat（热力格）· table（四式表格）

### 4.2 ECharts 实现约定

- 每 kind 一个渲染函数（对应 FTEngine FTK 的 plot/season/monthly，按 ECharts 重写）
- 图内字体/浮窗/格式（日期、数字、单位）规范随 design/charts 移植
- 两级浮窗、复制钮、整卡截图沿用 FTEngine 交互规范
- 图表体检规则（CK 前缀）移植为 ECharts 版 chart_lint
- 暗色主题以 ECharts theme 注册实现（§2.3 令牌）

### 4.3 期货交易图表

- K 线等金融图表优先 ECharts candlestick + dataZoom；盘口级需求再引入 KLineChart（同设计语言）

### 4.4 交付物中的图表块

- 图表是交付物块的一种（§5.2），渲染仍走 chart-spec 编译（§5.1）
- **版本对比**：同一图两版本并排或叠加，高亮数据变化；随交付物版本进入 diff
- **溯源**：图表块记录 series_id / 表 id 与数据快照；来源徽与状态徽同 §2.4

## 5. chart-spec 与交付物块模型

### 5.1 chart-spec

- 图表 = `{template_id, series_bindings, overrides}`；编译产物 = ECharts option JSON
- **v1 固定模板**：模板库只读，绑定数据即出图
- **v2 用户自定义**：编辑器改 overrides（轴、配色、格式、叠加序列），spec 可保存/共享
- agent 生成图表 = 产出 spec；溯源 = spec 中每个 series_id 可查

### 5.2 交付物块模型（D-016）

交付物 = **有序块 + 元数据**（作业、版本、定稿状态 `draft / final`、作者）。

| 块类型 | 内容 | 溯源 |
|---|---|---|
| 结论 | 结论文本（可带置信 / 待确认标记） | 证据锚（断言 / 观测） |
| 图表 | chart-spec + 绑定 | series_id / 数据快照 |
| 表格 | 表引用或内联表 | table_id / 数据快照 |
| 引用 | 外部材料摘录 | source_id + 页 / 块定位 |
| 待验证 | 验证性需求卡 | 回链结论块 |
| 备注 | 人的说明 / 批注（不进结论） | 作者 + 时间 |

- 每块有 id、状态（草稿 / 暂定 / 已确认 / 冲突）、来源徽、批注线程
- 版本 = 块集合快照；diff 按块呈现；定稿 = 不可变快照（语义与效果：`interaction.md` §3.5）
- chart-spec 是图表块的渲染输入（§5.1 不变），不直接绑定交付物
- 学习产物复用同一块模型（笔记 / 概念图块），但无定稿语义

## 6. UI 组件与布局（移植自 FTEngine design/UI，暗色适配）

- 卡片家族与图卡契约、卡高档位
- 表格四式：通用表、盘面网格、卡内小表、大平衡表/季度表
- 组件：胶囊、徽章、灯、芯片、页签、脚注、浮层、空态
- 新增组件（D-016）：阶段轨道、作业卡、产物卡、来源徽、状态徽、冲突芯片、diff 视图、块批注、验证卡、协议卡、学习卡；移植 / 自制决策随实施登记
- 界面色令牌（CSS 变量）、字体栈（三族分工）、字号阶梯、间距圆角
- 桌面适配：暗色玻璃外壳、侧栏导航、窗口 / 托盘、设置页、作业页、格物致知

## 7. 交付物与学习产物设计

- **交付物类型**：日报（定时作业模板）、专题、临时答复、验证更新、学习产物
- **日报**沿用 D-011 设计理念：按用户关注点 + 用户自己的分析逻辑组织，结论先行 → 图表证据 → 数据溯源；v1 固定模板，v2 用户可配
- **交付物 = 块的有序集合**（§5.2）：可编辑、可批注、版本化；定稿 = 不可变快照；编辑痕迹用黛驼中性色，不与行情涨跌红绿冲突
- **改稿**：块批注 / 直接编辑 / 下指令 → agent 产出新版本 + diff，人可接受 / 回退
- **验证性需求**：交付物末尾"待验证"区 + 验证队列入口；每张卡可继续 / 稍后 / 丢弃（`interaction.md` §3.6）
- **学习产物**：笔记 / 概念图 / 复盘摘要 / 待验证问题；标注"派生"与学习会话谱系；无固定版式，阅读优先
- **溯源是设计元素**：每个数字 / 结论可点回来源；派生内容标注"内部生成"并附根来源索引（D-018 §2）

## 8. 规范资产移植计划

- `design/charts/`：FTEngine design/Graphs 各条目文件（Base/Kinds/Palette/Seasonal/Tooltip/Formats/Copy/Lint_Rules）
- `design/ui/`：FTEngine design/UI 各条目文件（Layout/Cards/Tables/Colors/Fonts/Components/Foundations）
- 原则：实现对应模块时按需逐份搬运并登记，不一次性搬空；每份保留原条目 id 与"为什么"
- 新增组件与状态 / 来源语义（D-016）随实现逐份登记到 `design/ui/`；状态色令牌在实施阶段登记数值，不在本文先定值
- 注：`specs/` 目录留给功能规格（spec-driven 工作流，见 AGENTS.md §2），规范资产统一放 `design/`
