# D-017 知识回写闸门与断言台账

- 日期：2026-10-28
- 状态：accepted

- 相关：`plan.md` §3/§8/§10、`architecture.md` §4.1/§4.4/§4.6/§4.7/§5.2、`interaction.md` §5、D-016
- 编号说明：见 `plan.md` §3 编号说明（D-015 预留）

## 背景

"人 + agent 生产的内容是否应该进入数据库被 agent 学习与调用"是本架构的关键问题。若一律禁止，工作流无法自迭代；若不加限制地回流，会出现三类污染：

1. **重复与膨胀**：同一事实换措辞/换报告反复入库，检索上下文被同义内容挤占；
2. **丢失互证**：简单按"库里已有就不放"处理，会丢掉"同一事实多来源"这一最有价值的信号；
3. **自引用回音室**：agent 自己的结论回流后被当作外部证据检索，形成自我复读、置信虚高。

2026-10-28 Walter 确认原则：来源可正确溯源即可入库，但必须去重；"数据库中已存在的内容不被放入"需要细化为可执行的判定规则。

## 备选方案

- **A（采纳）**：内容分三类（源材料 / 断言 / 派生），分层判定；写入闸门 L0–L5；断言台账为去重单位；派生内容隔离并设晋升门；分级抽取控制成本
- B 仅做文档级去重 + 派生内容不入库：实现最简，但丢失多源互证与修订/冲突信号，交付结论也无法沉淀
- C 全量断言抽取（所有外部文档都抽断言）：成本与噪声不可接受；外部文档多数只需检索级去重
- D 靠人工审核所有写入：不可持续，也无法覆盖每天数百个文档块

## 结论

1. **三类内容、三种入口**：源材料（不可变、指纹去重）；断言（去重单位，可被人/agent 生产，须回链来源）；派生内容（结论/观点/笔记/图表摘要，带推导 DAG，`origin=derived`，不进入"独立证据"计数）
2. **写入闸门 L0–L5**：L0 溯源完整性 → L1 原文指纹 → L2 块级近重 → L3 断言归并 → L4 派生隔离与晋升 → L5 检索期去重；判定规则（含六种情况）权威在 `interaction.md` §5
3. **去重语义 = 归并 + 加边**，不是丢弃：同断言同值 → 给已有断言加证据边（互证）；同槽位异值 → 新增 claim revision + 冲突标记（不覆盖，期货数据修订是常态）；同结论不同证据 → 作为独立派生保留（证据源相同则降权）
4. **断言台账**为结构化去重单位：`claims / claim_anchors / claim_edges / claim_revisions / conflicts`；存储与接口见 `architecture.md` §4.7
5. **派生隔离与晋升**：派生内容不得作为独立证据；经人工确认或独立外部源互证后可晋升为"已确认断言"（晋升留痕）；检索与 prompt 中显式标注"内部结论，非外部证据"
6. **人工可推翻**：合并/拆分/冲突裁定可被用户推翻，反馈进入规则与阈值调优；闸门每次判定留审计日志（why merged / rejected），保证可重算、可审计、幂等
7. **成本分级**：外部文档只做 L0–L2；人 + agent 产物与交付结论做 L3–L4。v1 先落 L0–L2 + 派生标记；L3 断言台账在知识库 v1 之后接入（`plan.md` §8）
8. **时序数据不适用本闸门**：时序去重仍为 D-012 的 `(series_id, ts, source, ingest_run)` 幂等语义

## 取舍理由

- **按对象分层**才能同时满足"能学习"与"不污染"：源材料不需要断言化，派生内容不该当证据，断言才是合适的去重粒度
- **加边而非丢弃**：保住多源互证、修订与冲突这些最有价值的信息，避免"去重把证据去没了"
- **派生隔离 + 晋升门**是防自引用的唯一可靠机制；没有它，知识自迭代会退化为置信度通胀
- **分级抽取**把 LLM 成本控制在可接受范围：每日需要断言化的只有人 + agent 产出，量级远小于外部文档
- **人工可推翻**保留了"只有人能补充"的最后一道判断权，也符合 D-016 的介入原则
