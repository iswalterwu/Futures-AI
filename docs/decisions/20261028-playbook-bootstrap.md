# D-024 分析协议冷启动：用户历史产出摄取与首启访谈

- 日期：2026-10-28
- 状态：accepted
- 关系：补充 D-016 §6（蒸馏来源从介入扩展到历史产出与访谈）、补充 D-017（用户历史分析入派生区，作者 = 人，不计独立证据）、补充 D-018 §6（蒸馏触发新增 bootstrap）、补充 D-019（由蒸馏员执行，访谈模式）；修订 `plan.md` §8 排序原则 2；不取代任何 ADR
- 相关：`interaction.md` §3.4/§5.1/§6.1/§6.2/§6.6（新）、`architecture.md` §4.4/§4.6/§5.2/§5.5/§8、`designUI.md` §3.4/§3.8、`plan.md` §3/§8

## 背景

`plan.md` §8 排序原则 2 说"分析协议蒸馏需要至少数周的介入记录，冷启动蒸馏容易拍脑袋"，因此格物致知与自动蒸馏后置。但这忽略了一个事实：目标用户通常有**几年的历史报告、笔记、Excel 模型**——他们的框架、常看指标、措辞与反复出现的问题早已写在里面；再加一次结构化访谈，隐性知识也能采到一部分。首周"agent 完全不像我"的体验是可以避免的。

2026-10-28 第三轮 Walter 裁定：协议冷启动（摄取用户历史产出 + 访谈）进 Phase 1。

## 备选方案

- **A（采纳）**：Phase 1 加 `playbook-bootstrap`：历史产出摄取 → 蒸馏员抽 proposed 规则；首启结构化访谈 → 画像 / 关注点 / 协议候选；全部经透明页确认，不自动 active
- B 等待介入积累（原方案）：数周冷启动，首周体验差
- C 预置通用"油品分析师"协议：不像用户，且可能与用户框架冲突；作为可导入的协议包候选（D-023 主体）保留

## 结论

1. **历史产出摄取**：用户指定历史产出目录（报告 / 笔记 / Excel 模型）→ 知识层摄取（L0–L2）；分类为**用户历史分析**：`origin=derived`、作者 = 人、`source_kind=user_history`。其中引用的外部数字可抽为断言，但来源须回链原始源；回链不到的标"用户转述"，不计独立证据（D-017 / D-018 §2 不变）。
2. **蒸馏**：蒸馏员读历史产出 → 候选：框架条目、常看指标与图表偏好、表达结构、反复出现的问题与关注点 → `proposed` 规则（证据 = 文档定位）。门槛：复发 ≥2 份文档，或用户在透明页显式确认；`source=bootstrap` 与介入蒸馏分开登记；**不自动 active**。
3. **首启访谈**：首次启动（或随时在"Agent 学到的"页重做）由蒸馏员以结构化问题采集：每日先看什么、关注品种 / 地区 / 合约、分析框架、什么算证据与禁区、表达偏好。答案 → 画像（`memory/profile/`）、关注点（`memory/focus/`）、协议候选；访谈记录为介入事件 `kind=interview`；可跳过、可重做。
4. **防护**：过拟合防护与显式教导优先不变（§6.5）；冷启动规则可整体停用 / 回退；历史产出中的立场不生成 call（历史判断不进校准，D-020 只从定稿起算）。
5. **路线图**：Phase 1 新增 feature `playbook-bootstrap`（依赖知识库 v1 摄取管线 + "Agent 学到的"透明页最小版）；排序原则 2 修订为"格物致知晚于介入积累；协议冷启动不等介入"。
6. **工具**：`playbook_propose`（已有）、`profile_write`（新增；蒸馏员访谈模式，写 `memory/profile` / `memory/focus`）。

## 取舍理由

- **存量产出是最便宜的协议来源**：几年的报告比几周的介入信号密度高得多，且是用户自己写的、无歧义。
- **派生区而非外部证据**：用户历史分析是"人的派生"，入可信区会让用户的旧观点变成"外部证据"回流，形成自引用。
- **proposed 而非 active**：冷启动规则没有经过介入验证，必须由用户在透明页确认；显式确认是最强信号，与 D-018 定稿同理。
- **访谈可跳过**：不把首启做成问卷墙；随时可重做意味着它也是一种显式教导入口。
- **历史立场不进校准**：历史判断的时间、依据与当时信息不可重建，混入校准会污染样本。
