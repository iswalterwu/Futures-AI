# D-021 世界模型（活平衡表）为一等对象：槽位视图、两视图、一致性门与求解

- 日期：2026-10-28
- 状态：accepted
- 关系：补充 D-017（世界模型是断言台账之上的视图 / 物化，不新增存储；新增闸门 L3.5 模型一致性门）、补充 D-012（观测是槽位值来源之一，时序语义与单写者不变）、补充 D-016（交付物中的数字是模型投影；新增介入 kind `slot_fix`）、补充 D-019（一致性门是代码，对账员只做解释与建议）；不取代任何 ADR
- 相关：`interaction.md` §2.1/§2.2/§3.4/§5.2/§10（新）、`architecture.md` §1/§2/§4.1/§4.4/§4.7/§5.2/§8、`designUI.md` §3.4/§6、`plan.md` §2/§3/§5/§8/§10、D-020、D-022、D-023

## 背景

`plan.md` §1 痛点 #3 是"油品全球平衡表这类活框架缺乏持续迭代的实操性"，但现有设计里**没有对应的对象**：知识层是源材料 / 断言 / 派生三类内容加闸门，交付物是块，冲突在队列里，验证需求在卡片里——"市场现在是什么状态"这件事散落在各处，没有一个随时被更新、求解、质询的结构。

D-017 的断言台账 `{主谓宾 / 值, 期, 地区, 单位, 口径, 极性}` 本质上已经是一个世界模型的事实存储，差的只是：品种包给它一个 schema、agent 承担维护职责、一致性成为闸门、交付物从它投影。2026-10-28 第三轮 Walter 裁定：世界模型可以成为一等对象。

## 备选方案

- **A（采纳）**：世界模型 = 品种包 schema 定义的槽位集合，槽位值由断言台账与观测投影 / 物化；两视图（基本面 / 市场隐含）；品种包声明恒等式，一致性为闸门 L3.5；求解 / 敏感性 / 情景后置
- B 平衡表只是一个交付物模板（表格块）：不能求解、不能产生冲突与验证需求、不能跑情景；痛点 #3 不解
- C 独立的知识图谱 / 本体数据库：与断言台账双份、漂移，过度工程

## 结论

1. **定义**：世界模型是一个品种包 schema 定义的市场状态**槽位集合**；一个品种包一个模型；底座品种无关（schema 是插件内容，`plan.md` §7.1）。**不是新存储**：槽位值由断言台账（claims）与观测（observations）投影 / 物化而来，谱系与版本沿用 D-017 / D-012。
2. **槽位** `{key（量 / 地区 / 期 / 口径）, 值, 单位, 置信, 来源集, 更新时间, 陈旧度, 值类型（观测 / 断言 / 估计）, 状态（草稿 / 暂定 / 已确认 / 冲突）}`。估计 = 求解器、agent 或人填；人填的值作者 = 人，**agent 不得覆盖**（可标冲突，D-020 用户优先）。
3. **两视图**：**基本面视图**（供需 / 库存 / 流向 / 开工 / 成本…）与**市场隐含视图**（曲线、价差、持仓…）。"基本面 vs 市场隐含"的分歧是模型的一等查询，油品 v1 schema 必含；分歧 → 分析台结论候选 + 验证性需求来源。
4. **一致性**：品种包声明**恒等式**（如 供给 + 进口 + 期初库存 = 需求 + 出口 + 期末库存）与允差。**模型一致性门 L3.5**：断言落入槽位时检查恒等式与同槽位冲突；违反**不拒绝** → 标冲突 + 进 D-017 冲突队列 + 产生验证性需求。门是代码（`backend/knowledge/worldmodel/`），对账员角色只做解释与建议。
5. **求解（后置）**：恒等式残差分配、估计填补、**敏感性**（各输入对关键槽位 / 在持观点的影响，作为议程排序的输入，D-022）、**情景**（"若…则…"在模型上传导，用户修枝）；v1 非目标。
6. **投影**：平衡表页、相关图表块、晨间议程中的数字由槽位渲染，带来源徽 / 状态徽 / **陈旧徽**；人改槽位 = 介入事件 `slot_fix`（走版本与闸门，不直写）；交付物定稿冻结所引用槽位的版本（纳入 D-018 定稿效果 ①）。
7. **与数据层的边界**：时序观测仍只在数据层；模型只引用 `series_id@asof`，不复制；D-012 决胜链与幂等语义不变。
8. **工具**：`model_query`（读槽位 / 分歧 / 残差 / 陈旧）、`model_update`（带槽位 key 的 `kb_write`，必经闸门含 L3.5）。
9. **范围**：Phase 2A 落油品 schema v1 + 槽位视图 + 一致性门 v0（只检查、只标记）+ 平衡表页投影；求解器 / 敏感性 / 情景 Phase 2D。

## 取舍理由

- **视图而非新库**：断言台账已经是事实存储，再建一份就是双份漂移；世界模型只加 schema、投影和恒等式检查。
- **两视图**：交易员的核心问题是"我在哪里与市场不一致"，只有把市场隐含视图放进模型，这个问题才是一个查询而不是一篇文章。
- **一致性门只标不拒**：期货数据修订与口径差异是常态，拒绝会把真实冲突挡在门外；标记 + 冲突队列 + 验证需求才是"活框架"的迭代机制。
- **先视图后求解**：schema 未稳就上求解器会把估计写进模型、污染可信区；先让投影与一致性跑起来。
- **人填不可覆盖**：人填槽位是"只有人能提供"（§3.1）的典型，agent 覆盖等于否定该原则。
