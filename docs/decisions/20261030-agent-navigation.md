# D-026 开发导航与 agent 阅读策略：单一短入口、外置开发规则、按任务触发读取

## 背景

- 根 `AGENTS.md` 约 19 KB，同时承载身份说明、完整 spec-driven 工作流、产品决策复述、模型路由全文。每个会话都要整份载入，且 §3 用自己的措辞复述 ADR 与 `docs/` 已有规则，形成第二份政策文本，存在漂移风险（`docs/plan.md` §4 文档纪律已要求“README 只导航不复制数值”“每份规范只有一个权威作者位置”）。
- `docs/plan.md` 约 40 KB，除产品方案外还含已完成的 D-015 重编号叙述与 §9 的路由 / 集成 / 验证日志；`specs/README.md` 单个状态单元格超过 2 KB。当前规则与历史证据混在默认阅读路径上，难以定位。
- 原阅读策略有两处与实际工作方式不符：①“任何任务前先读 plan.md”让局部小修也必须载入完整产品方案；②“每一步重新读取、不依赖会话记忆”在同一上下文中会重复追加完全相同且仍完整可见的原文，却没有处理真正的风险——上下文被压缩 / 截断后只剩摘要、或输入在阶段之间已经变化。

## 备选方案

| 方案 | 内容 | 结论 |
|---|---|---|
| A 维持现状 | 不改 | 否：漂移与定位问题持续 |
| B 只压缩 AGENTS | 删减细则以缩小体积 | 否：会丢失仍有效的要求 |
| C 外置细则 + 按任务导航（采纳） | 根文件保留硬约束与触发表；工作流、模型路由各有单一详细权威；产品决策链接到现行权威章节；历史逐字迁入维护快照 | 是 |
| D 引入上下文装配工具 / 框架 | 用脚本自动拼装上下文 | 否：违反 AGENTS §5 第 7 条（不引入仓库没在用的工具或流程） |

## 结论

1. **根 `AGENTS.md` 仍是每个会话必读的唯一常驻入口**。保留 §0–§6 标题；Gate、Checklist 保护、spec 冻结与变更、隐私 / 凭证 / 审计、工作区纪律、模型路由的硬约束始终在根文件可见；§5 七条工程准则逐字保留。体积软目标约 6–8 KB，不为达标删除要求。
2. **[`docs/development/workflow.md`](../development/workflow.md)** 成为 spec-driven 工作流（原 §2）的单一详细权威；步骤编号 1–11 保持不变，旧引用“AGENTS §2 第 N 步”解析到同号步骤。
3. **[`docs/development/model-routing.md`](../development/model-routing.md)** 成为开发工作流模型路由（原 §6）的单一详细权威；阶段→模型表与八条规则原文迁移，规则编号不变；根 §6 保留为兼容入口与硬约束摘要。并行写入的隔离细则只在其规则 7 维护，workflow 链接过去。
4. **[`docs/README.md`](../README.md)** 记录文档权威归属与直接任务路由；它不是每个任务前必须先读的中间索引。
5. 根 §3 只保留全局产品护栏（本地优先、溯源与派生隔离、用户判断优先、显式定稿）和原文入口；“主题 → ADR → 现行权威章节”的详细导航表放在 `docs/README.md`，不在根重复。相关时，被链接原文中的详细规则仍是强制要求。
6. 历史内容逐字迁入 `docs/maintenance/` 快照（代码围栏、源路径、基线、源行号、SHA256）：`docs/plan.md` 已完成的 D-015 编号叙述与 §9 历史批准 / 路由 / 集成记录、`specs/README.md` 旧状态表与跨 feature 表。`plan.md` §3 / §9 标题与锚点保留并链接快照；仍有效的边界留在活文档中。在研 feature 增加只导航的 `README.md`，不另立状态权威。
7. **两项阅读策略变更**（实质变更，不是机械迁移）：
   1. **`docs/plan.md` 按触发必读**：任务涉及产品定位、范围、路线图 / 分期、跨领域设计或新 ADR 时必读相关章节，并作为其他任务的相关上下文；不再要求每个琐碎任务（如不影响范围的单模块局部修复）都先读全文。拿不准是否涉及时，读。
   2. **阶段输入核对**：每个阶段开始时核对本阶段权威输入的实际版本（提交 SHA 或文件 hash）与其在当前上下文中的可见性；已变化、不在当前上下文、被压缩 / 截断或只剩摘要的输入，重读原文；完整可见且版本未变的原文，不再重复追加同一份。摘要、会话记忆、HANDOFF 转述**不得**替代已批准的 spec / AC / Gate / 安全规则原文，也不得替代审核必需的原始输入（spec、plan、tasks、实际 diff）。根 `AGENTS.md` 始终必读。阶段产物头部以纯文本记录一份小清单：输入路径 @ 提交 SHA 或文件 hash + 适用章节。新开的独立会话（如审核员 A）当前上下文中没有任何输入，因此按规则读取全部原文。
8. **兼容映射**：旧 §2 第 N 步 → workflow 第 N 步；历史“§2.1”（旧分支用语，指模型路由）→ model-routing；§4 → 根 §4；§5.x 不变；§6 规则 N / §6.N（含历史“§6.7 隔离”）→ model-routing 规则 N。
9. **纯文档记录位置说明**：model-routing 引用解析表将既有纯 docs 维护先例显式定位到 `docs/maintenance/`（基线 plan §9 已有“纯 docs 任务，无 feature 目录”先例）。这是规则 4 的记录位置说明，不改变模型 / 通道 / 回退策略，不为功能开发提供免走 `specs/` 或 Gate 的豁免。

## 不变的内容

Gate 1 / Gate 2、Checklist 由独立审核员勾选且实施者不改、Analyze 只读后修复再跑、Converge / Review 判定（P1/P2 = 未通过）、Handoff 证据与 PR / merge / 冲突纪律、feature 状态表与依赖规则；模型名称、Claude 通道顺序、回退顺序、“只有调用失败才回退”、限额窗口内不重试、审核员独立性、派工记录、并行隔离、产品与开发路由分离；D-019、D-025；全部冻结 spec / AC / checklist、历史 ADR / review / converge / 日志原件。本决策**不**新增 token / 金钱 / 时间预算、自动修复次数上限、自主度、产品义务，**不**放松任何闸门。

## 取舍理由

- 单一详细权威消除根文件与 `docs/` 之间的双份政策；根文件保留硬约束，避免“只看入口就漏掉强制规则”。
- 代价是文件数增加、读者多跳一次。以根 §1 触发表直接指向权威文件抵消；明确“链接不是传递性必读”，同时规定“不确定领域时查看改动范围并扩大阅读，导航不得用来跳过实际适用的规则”。
- 阅读策略变更 2 的风险是被误用为“不重读”的借口；以明确的重读条件、“摘要不得替代原文”与输入清单约束。
