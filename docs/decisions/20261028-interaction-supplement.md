## 备选方案

- 定稿：A 显式人工动作（采纳）/ B 草稿定时自动定稿 / C 无定稿概念、以最新版本为准
- 派生引用：A 可引用 + 标注 + 根来源索引 + 不计独立证据（采纳）/ B 禁止引用为证据（D-017 原措辞偏向）/ C 不加区分
- 网页剪藏：A Backend 抓取 + 正文抽取 + 模型清理 + 数字守恒校验 + frontmatter .md（采纳）/ B 只收粘贴文本 / C 浏览器渲染抓取（留 Phase 2）
- 处理台修正值：A 复用 `local_file` 导入 + 用户清单（采纳）/ B 新增内置 `manual` 源（需 data-layer spec 修订）
- 命名：A "格物致知"（采纳）/ B "学习"
- 蒸馏：A 定稿后即时 + 夜间合并 + 手动（采纳）/ B 作业收尾 + 每周整合

## 结论

### 1. 定稿（取代"发布"一词）

- **定义**：定稿 = 用户对某个交付物版本的一次显式接受动作，状态 `draft → final`。它是"我审过了，这就是我的产出"的唯一明确信号；**不自动定稿**（定时作业长期未定稿 → N 天后标"未审阅"归档：不晋升、不回流）。
- **效果（按序）**：① 冻结：版本 N 快照（块 + 引用的断言版本 + chart-spec + 数据 asof）不可变，再改 = 新草稿 N+1；② 升级：留在 N 中的派生断言 → 人工确认（`confirmed_by: deliverable@N`，即 D-017 晋升门的"人工确认"）；本会话中被删的 → `rejected_by_user`；被改的 → 新 revision supersedes、来源 = 人；③ 回流：确认内容经写入闸门入知识底座；④ 派生：抽取验证性需求 → 验证队列（非阻塞）；⑤ 蒸馏：读本会话介入事件 → 分析协议候选；⑥ 导出（可选，亮色纸底）。
- **不是什么**：不阻塞（今天的作业不等昨天定稿；未定稿草稿永远是草稿，其断言留在派生区）；不可撤销（要改就出 N+1 再定稿，N 标 superseded；N 有而 N+1 无的断言在 N+1 定稿时记 rejected）；不是块级（块级动作随时记介入事件，定稿只是把它们结算为接受 / 拒绝）。
- **显式介入 vs 隐式接受**：改 / 删 / 追问 / 深挖无论定稿与否都是学习信号；"留着没改 = 认可"**只在定稿时成立**。
- 作业状态 `delivered` 保留（指作业已交付）；交付物状态用 `draft / final`。定稿属破坏性动作，二次确认（D-016 R4 不变）。导出 / 外发仍是独立动作。
- 效果 ③④⑤ 依赖后续 feature（闸门 L3、验证队列、蒸馏）；v1（Phase 1.5）定稿只做 ① + 派生标记。

### 2. 派生内容的引用策略（细化 D-017 结论 5）

派生内容（`origin=derived`）**可被引用为证据**，但引用必须：(a) 标"**内部生成**"（界面来源徽文案）；(b) 附**根来源索引**——沿推导 DAG 算出的外部源根集合（`doc_id+page` / `series_id@ts`），可逐级点回；根集合为空的额外标"推断"；(c) **不计入独立证据数**：佐证强度只按不同根来源计数，agent 复述不加分。D-017 的派生隔离、晋升门、检索降权不变。

### 3. 网页剪藏入库规范

1. 入口：全局投放 / 作业内采集台 / 输入栏粘贴 URL、HTML 或文本；文件与网页共用同一套来源说明（用途、可靠性三档、时效、口径）。
2. 抓取：用户触发即授权，URL + fetched_at 记介入事件；v1 为 Backend HTTP + 正文抽取（readability 类），抽不到时提示粘贴页面内容；浏览器渲染抓取留 Phase 2；agent 触发剪藏随 Phase 2B（持续研究）。
3. 正文 → markdown：表格必须保留为 md 表格，图片保留链接；元数据 title / author / published_at / canonical URL / site。
4. **模型清理与排版**：由"剪藏员"角色（D-019，fast 档、**零工具**）去导航 / 广告残留、修正标题层级、规整表格；**硬规则：数字逐字不动**，清理后做**数字守恒校验**（清理稿数字 token ⊆ 原始抽取），不通过则回退原始稿并标记。零工具 + 校验 = 网页提示注入的防线。
5. 落盘：Obsidian 式 `.md`，YAML frontmatter（title / source_url / canonical_url / author / published_at / fetched_at / site / origin / trust / purpose / tags / content_hash）→ `<数据目录>/clips/<date>-<slug>.md`；原始抽取稿存 `parsed/`；不写入只读的 `docs_in/`。
6. 入库：标准摄取管线（闸门 L0–L2；L1 = canonical URL + 正文 hash）；chunk → clip_id + section → source_url。

### 4. 处理台与 data-layer 既有机制的映射

| 典型错误 | 用户动作 | 底层机制 |
|---|---|---|
| 两源同序列、差的赢了 | 换来源 | `config priority`（D-012 决胜链） |
| 源符号映射错 | 修正别名 | `config alias`（手动 > manifest） |
| 单点值错 | 手工修正值 + 备注 | `import` 经 `local_file` 适配器写入用户清单源（如 `manual-fixes`，高优先级）；**不新增内置源、不改 data-layer spec**；摩擦出现再评估内置 `manual` 源 |
| 源停更 / 不可信 | 禁用来源 | `config enable/disable` |
| 口径不一致 | 裁定口径 | 对账报告（R-006）+ 用户裁定 |
| 表格错列错单位 | 修正表卡 | 表卡覆盖 + 按文档类型的解析提示（知识层） |

介入事件只存对 data-layer 记录的引用（不复制数据）；动作后依赖该数据的断言 / 块置暂定，agent 在下一检查点只重算受影响部分。介入 kind 扩展：`source_pref`（换源 / 禁源 / 优先级）、`value_fix`（手工修正值）。

### 5. 命名：格物致知

- 产品区、左侧菜单、模式统一为"**格物致知**"（取代 D-016 结论 9 的"学习"）；二级导航：**阅读 · 复盘 · 深挖 · 笔记**（发散是深挖 / 复盘内的动作，自测归阅读 / 复盘）。
- 概念层"学习循环 / 学习产物"保留原词；代码目录 `backend/learning/`、路由 `/learning` 不改。

定稿后即时（本会话介入）+ 夜间合并（含未定稿草稿的显式介入、跨日压缩与去矛盾）+ 用户手动；取代"作业收尾 + 每周整合"。门槛（复发 ≥2 或显式教导）不变。

## 取舍理由

- 定稿显式：系统无法区分"没看"和"看了没意见"，所有隐式确认都依赖"用户确实审过"；回流 / 晋升 / 派生 / 蒸馏需要一个结算边界；复盘需要"当时我信什么"的冻结快照。不做撤销，少一个状态。
- 派生可引用但不计数：禁止引用会让 agent 无法利用自己的历史分析；只要标注 + 根来源可追 + 不计独立证据，就既可用又不形成回音室。
- 剪藏模型清理 + 数字守恒：金融网页正文噪声大，纯规则清理质量不够；但清理模型不能改数字，守恒校验把风险压到零工具 + 可回退。
- 处理台复用既有机制：工程准则 #1/#7，不为猜测的需求改封闭枚举。
- 格物致知：产品语义（研习以致知）比"学习"准确；概念词与代码标识不改以降低同步成本。
- 蒸馏按定稿 + 夜间：定稿是最强的接受信号，夜间合并处理未定稿的显式介入；每周整合太慢。
