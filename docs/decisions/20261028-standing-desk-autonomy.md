# D-022 常驻研究台与自主度分级：常驻作业、晨间议程（日报降为导出）、A0–A3

- 日期：2026-10-28
- 状态：accepted
- 关系：补充 D-016（作业类型新增常驻作业；"模块看、作业做"加"常驻作业值班"）、变更 D-016 / D-011 对日报的定位（"日报 = 定时作业的交付物模板" → 晨间议程为主产物、日报为导出模板；焦点带承载议程头部）、补充 D-018 §6（夜间合并扩展为夜间整合）、补充 D-019（常驻作业节点由角色执行；新增值班员角色；预算叠加）；不取代任何 ADR
- 相关：`interaction.md` §1.3/§2.1/§2.2/§2.4/§3.6/§3.7/§11（新）、`architecture.md` §1/§2/§4.4/§5.2/§5.5/§6/§8/§9、`designUI.md` §3.1/§3.2/§3.4/§6/§7、`plan.md` §2/§3/§5/§7.4/§8/§10、D-020、D-021

## 背景

现有设计里 agent 是**被动**的：作业由人或定时器创建，其余时间闲置；用户打开软件时桌上没有东西。而研究台的标准动作——发布前做预期、发布后算 surprise、新数据对照在持观点、新材料自动入库——全部可以在无人时完成。同时"日报"继承了数据供应商的形态（一篇文档），而用户每天真正需要的是"变了什么、哪些需要我决定"。

2026-10-28 第三轮 Walter 裁定：agent 自主度做成一个**功能**，不同用户可开启不同程度；日报**降为导出**，但仍以提供信息为主。

## 备选方案

- **A（采纳）**：新增常驻作业类型（触发器驱动、引擎调度）+ v1 职责集（台）+ 晨间议程为主产物、日报为导出 + 自主度 A0–A3 分级 + 预算
- B 维持定时作业（日报）作为唯一自动化：简单，但 agent 仍被动，无预期表 / surprise / 一致性报警
- C 完全自主 agent（自行创建作业、自行扩展）不分级：越权与成本不可控，且违反 D-019"编排在代码里"

## 结论

1. **常驻作业（standing job）**为作业类型：`{职责, 触发器（日历 / 数据写入事件 / 价格或序列阈值 / 文件系统事件 / 定时）, 作用域（品种 / 序列 / 作业）, 产物类型, 自主度要求, 预算}`。由作业引擎按触发器调度（编排仍在代码里，D-019）；产物进收件箱 / 议程 / 平衡表页，不弹窗（R6）。
2. **v1 职责集（"台"）**（集合由 feature spec 冻结）：
   - **晨间台**：装配晨间议程；
   - **数据台**：发布前预期表（季节性 / 历史 / 一致预期）→ 发布后 surprise；修订与异常标记；
   - **一致性台**：新数据对照在持观点 / call / 人填槽位，交付物块标"依据已变"，触发 call 裁决（D-020）；
   - **图书馆员**：`docs_in/` / `clips/` 新材料自动摄取、断言陈旧标记；共识地图后置；
   - **教练**：call 裁决后排程复盘（D-020）；
   - **夜间整合**：D-018 §6 的夜间合并扩展为"协议合并 + 断言归并与矛盾 + 明日预期表预算"。
3. **晨间议程**为常驻作业主产物：条目 = 变化 / surprise / 依据已变 / 到期 call / 待裁冲突 / 待介入；排序 = 变化幅度 × 与用户在持观点和关注的相关度 × 决策临近度（规则由 spec 定；D-021 敏感性落地后作为输入）；每条下钻到槽位 / 块 / 来源；**焦点带承载议程头部**。
4. **日报降为导出模板**：仍以提供信息为主（结论先行 → 图表证据 → 数据溯源，固定模板不变），由议程 + 定时作业交付物生成；D-018 定稿语义适用于日报导出的**底稿**（定时作业交付物），**不适用于议程**（议程不定稿、不回流、过期归档）。Phase 1 的日报固定模板不变，作为导出模板的前身。
5. **自主度分级**（用户可配，可按作用域不同；档位名与默认档以 settings spec 为准，建议默认 A1）：

| 档 | 名称 | agent 可以 |
|---|---|---|
| A0 | 执行 | 只跑人 / 定时创建的作业；不主动提案 |
| A1 | 提案 | 提议作业、计划 DAG、子作业、验证卡、协议候选；人确认后执行 |
| A2 | 常驻 | 常驻作业自动运行并写收件箱 / 议程；可自动创建"验证追踪 / 裁决取证"类子作业（只读取数与登记） |
| A3 | 自扩展 | 在沙箱内编写适配器 / 图表模板 / 处理函数，经复核员（异模型）审查 + 人批准后注册；网络白名单；Phase 4 |

   任何档位：破坏性动作（删源、定稿、外发、清库）仍需人确认（R4）；写入闸门（D-017）、用户优先（D-020）、最小权限（D-019）不随档位放松。
6. **预算**：常驻作业有每日 / 每台 token 预算（叠加 D-019 每角色 / 每作业上限）；超预算降级为 A1 提案；预算与档位进设置，并在作业详情与议程可见。
7. **角色**：新增**值班员**（standing job 默认执行角色：预期表叙述、surprise 解释、议程装配、裁决建议；standard 档；只读 + `agenda_write` + `call_resolve_suggest`）；夜间整合由蒸馏员（协议）与值班员（断言 / 预期表）分工；角色文件随 feature spec 冻结。
8. **feature flag**：A2 / A3 与常驻职责数量作为 tier 候选（`plan.md` §7.4）。
9. **路线图**：Phase 2B 落常驻作业、数据台 / 一致性台 / 图书馆员 / 教练 / 夜间整合、收件箱、晨间议程、日报导出、A0–A2；A3 随 Phase 4（第三方适配器生态）。

## 取舍理由

- **standing job 而非新 agent**：它只是"带触发器的作业"，复用状态机、版本、介入与预算，不引入第二套编排。
- **议程 vs 日报**：日报是信息的容器，议程是注意力的分配；用户每天先要的是后者，前者保留为可导出的正式产物。
- **分级而非开关**：不同用户对"agent 替我做决定"的容忍度差异大；A1 默认让 agent 有主动性但每步可见，A2/A3 由用户主动开启。
- **A3 单列**：自写代码是唯一会扩大攻击面的档位，必须沙箱 + 异模型审查 + 人批准 + 网络白名单，且最后落地。
- **预算降级而非停机**：超预算不应让桌子空着，降为提案保留价值、控制成本。
