# D-020 真值锚与结果校准（L4）：calls、三方校准、决策日志与用户优先

- 日期：2026-10-28
- 状态：accepted
- 关系：补充 D-016（三层自迭代 → 四层；§6.4 指标新增结果指标与护栏）、补充 D-018（定稿效果 ④ 扩展为"抽取验证性需求与 calls"；复盘有了 agent 发起的通道）、补充 D-017（来源校准成为检索权重的新输入，不替代多源互证计数）、补充 D-019（裁决建议与复盘由既有 / 新增角色执行）；不取代任何 ADR
- 相关：`interaction.md` §1.3/§2.1/§2.3/§3.4/§3.5/§3.6/§4/§6/§9（新）、`architecture.md` §2/§4.4/§5.2/§5.5/§8、`designUI.md` §3.4/§5.2/§6/§7、`plan.md` §2/§3/§5/§8/§10、D-021、D-022、D-023

## 背景

L1–L3 自迭代与 §6.4 的全部验收指标（一次通过率、人改率、返工轮次、追问密度、交付周期）都以**用户满意度**为锚：它们衡量 agent 是否越来越像用户，不衡量判断是否越来越准。对交易员，研究的终点是对市场的判断对不对；一个只会讨好用户的系统会把用户的偏见学得越来越像。

2026-10-28 第三轮（agent 工作流 brainstorm 后）Walter 裁定：**在不显著降低用户满意度的前提下，以市场结果为真值锚**；但用户通常掌握模型不知道的隐藏甚至非公开信息，因此**用户判断的权限级别在大部分时候高于 agent 与校准信号**。

## 备选方案

- **A（采纳）**：新增 L4 校准层——可裁决的 call、到期自动裁决、按作者 / 来源分桶的三方校准、决策日志、自动复盘；校准结果以信息呈现（镜子），agent 不以校准覆盖人的判断；满意度指标作为护栏
- B 维持仅介入学习：实现最简，但产品永远只能"像用户"、不能"更准"；来源信誉没有客观依据
- C 市场结果优先于用户判断（agent 据校准自动降权用户规则）：忽视私有信息的不对称，会与用户对抗，满意度崩
- D 以纸面组合 P&L 为唯一真值：信号最残酷但噪声最大（执行、时机、风控混入），作为候选池条目而非核心

## 结论

1. **四层自迭代**：在 L1 产物 / L2 协议 / L3 知识之上新增 **L4 校准迭代**（calls 裁决 + 三方校准 + 决策日志 + 自动复盘），回答"判断是否越来越准"；L1–L3 定义不变。
2. **Call**：有可检验含义的结论在**定稿**时由 agent 抽取为 call `{陈述, 时限或触发条件, 裁决标准（数据 / 事件）, 置信, 作者（人 / 角色@主体）, basis, 回链块}`。call 是验证性需求的第五类（`interaction.md` §3.6），进验证队列；**agent 的 call 不需用户确认即可登记**（显式标作者为 agent，是 agent 对自己陈述的负责），用户可改置信、改裁决标准、丢弃，也可自己登记 call。
3. **自动裁决**：时限到期或触发满足 → 作业引擎按裁决标准取证（数据层序列 / 断言台账 / 事件）判定 `hit / miss / unresolved`；需要语义判断的由值班员角色（D-022）给出建议后交人裁定；裁决留痕（证据 asof、判定理由），人可推翻。
4. **三方校准**：按作者（agent 角色@主体 / 人）与来源分桶统计命中率与 Brier（按品种 / 类型 / 时限分桶）。用途：**agent 校准** → 协议规则置信、"本次应用规则"的权重参考、主体排序（D-023）；**来源校准** → 检索权重与共识权重的新输入（与 D-017 多源互证计数并列，不替代）；**用户校准** → 只向用户呈现（镜子），不自动调整用户规则的优先级或作用域。
5. **用户优先**：agent 不得因校准结果自动覆盖、停用或降权用户显式教导的规则（`pin_rule`）、用户确认的断言与人填的槽位（D-021）。校准结果以信息呈现——**镜子**：立场 vs 市场、跨作业一致性提示、被驳回证据的后验命中率；镜子可整体或按作用域关闭。显式教导与隐式学习分开登记（§6.5 不变）。
6. **依据类型 `basis`**：用户的判断、介入与 call 可标 `basis=private`（非公开 / 私有信息）：不要求溯源到知识库、不触发"来源呢"类质询、不计入来源校准；仍进入决策日志与用户自查校准。默认 `public`。
7. **决策日志**：用户的决策（观点、仓位意向、取舍）为对象 `{陈述, 方向, 依据块 / call, basis, 时间, 复盘链接}`；agent 从定稿交付物建议起草，到期协助复盘；v1 手工录入，不接券商账户。
8. **自动复盘**：call 裁决后由格物角色生成复盘草稿（当时说 / 结果 / 漏了什么 / 协议候选 / 来源校准更新），进格物致知"复盘"与收件箱，用户可忽略；复盘结论经透明页才成协议，门槛不变（§6.2），`source=postmortem` 分开登记。
9. **指标与护栏**：§6.4 新增结果指标（agent 校准分、surprise 捕获率、发布 → 洞察时延、call 裁决率 / 无法裁决率）；满意度指标（一次通过率、人改率、返工轮次、追问密度）作为**护栏**——任何以结果指标为目标的协议 / 模型 / 主体变更，若使护栏指标显著恶化（阈值由 feature spec 定）即回退。
10. **块模型**新增观点块（方向 + 失效条件 + 时限 + 置信）、call 块、决策块（`designUI.md` §5.2）；calls 与决策对象的生命周期由作业引擎管理（与验证性需求同级），评分与复盘在 `backend/learning/calibration/`。
11. **v1 非目标**：券商账户 / 成交导入、纸面组合、跨用户匿名校准基准（见候选池 `docs/agent/candidates.md`）。

## 取舍理由

- **锚到市场但不对抗用户**：真值锚解决"越学越像用户偏见"的问题；用户优先解决"模型不知道用户知道什么"的不对称；两者用"镜子（信息）而非覆盖（动作）"调和。
- **`basis=private` 是必要的逃生口**：没有它，溯源纪律会逼用户要么编造来源、要么不记录真实判断；有了它，私有信息判断能进决策日志而不污染来源校准。
- **agent 的 call 自动登记**：让 agent 对自己的每句可检验陈述负责，是校准有样本的前提；用户确认门只保留在"生成新作业"这一步（§3.6 不变）。
- **护栏而非双目标优化**：满意度与准确度不是权衡，是约束与目标的关系；用阈值回退比加权简单且可测。
- **先 calls 后组合**：call 的裁决是确定性的、可审计的；P&L 混入执行噪声，留作候选。
