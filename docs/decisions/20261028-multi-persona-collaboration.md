# D-023 多主体协作：主体（persona）、作业树、辩论协议与 crux

- 日期：2026-10-28
- 状态：accepted
- 关系：补充 D-019（主体是角色实例化时的视角参数，与角色正交；新增裁判员角色；编排者的分析阶段内派发不变；"双模型校验"已由复核员异模型覆盖，不重复）、补充 D-016（作业树：子作业由作业引擎创建）、补充 D-017 / D-018（主体互引不计独立证据，裁判只引根来源）、补充 D-020（主体是校准分桶维度）；不取代任何 ADR
- 相关：`interaction.md` §2.1/§3.2/§3.6/§12（新）、`architecture.md` §2/§5.2/§5.5/§8、`designUI.md` §3.4/§3.6/§6、`plan.md` §2/§3/§5/§7.2/§7.4/§8/§10、D-022

## 背景

D-019 解决了"不同难度的任务用不同模型与权限"，但一次分析仍然只有**一个视角**：分析员按一套协议出一个结论，"主动提反证"是同一个脑子的自省。市场研究的价值常在分歧——多头与空头各自最强的案例是什么、分歧的 crux（若知道即可裁决的事实）是什么。单视角也无法让用户拿"现货贸易员框架"和"宏观框架"对同一证据各跑一遍。

2026-10-28 第三轮 Walter 裁定：建立多个不同人格和关注点的多模型主体，并行以不同方式协作 / 辩论。

## 备选方案

- **A（采纳）**：主体（persona）作为角色的视角参数；作业树（子作业并行）；辩论协议 + 裁判员 + crux；用户人格红队可选；成本每作业可选
- B 单主体 + prompt 内自我反证：便宜，但同一模型同一上下文的自我批评弱，无法产出真正的 crux
- C 固定三角色（多 / 空 / 裁判）硬编码：不够灵活，用户无法定义"现货贸易员 vs 宏观"这类视角

## 结论

1. **主体 Persona** = 角色实例化时的视角参数，与 D-019 的角色**正交**：角色定"做什么"（分析员 / 撰稿员…），主体定"以什么视角 / 框架 / 模型做"。`{id, 名称, 关注点与框架（引用分析协议子集或导入的协议包）, 模型绑定（档位或指定物理模型）, 作用域}`；用户可建 / 改；系统内置：基准、多头、空头、红队、**用户人格**（由协议 + 画像生成）。主体产物来源徽为 `agent:<角色>@<主体>`。
2. **作业树**：作业可有子作业（按主体，或按分解维度：供应 / 需求 / 物流）；子作业由**作业引擎**创建（人发起或 A1 提案，D-022），各自跑固定 DAG，产物与介入独立版本化；父作业在分析阶段合成。D-019 编排者的"分析阶段内派发子任务"不变，是作业树之外的轻量形态；pi 仍不推进阶段。
3. **辩论协议**：同一证据集（冻结 asof）→ 各主体的分析员各出最强案例（结论 + 证据链 + 预死亡分析"若三个月后错了，最可能为什么"）→ **裁判员**角色（新增：strong 档、只读、默认异模型）产出分歧地图 + **crux**（若知道即可裁决的事实、期望来源、裁决标准）+ 共识部分；crux → 验证性需求的新来源（可直接成 call，D-020）；用户在分析台看辩论视图，可裁定、追问任一主体。
4. **用户人格红队**：交付前可选一轮（默认关）：用户人格主体按协议生成预期反对意见，撰稿员先回答。红队产物是分析阶段产物（版本化、`origin=derived`），**不是介入事件**（作者 = agent）。
5. **防自引用**：主体互相引用不计独立证据；辩论产物 `origin=derived`；裁判不得引用主体结论作为证据，只能引用根来源（D-018 §2）。
6. **校准**：主体是 D-020 校准的分桶维度；用户可按校准排序 / 停用主体；校准不自动停用用户自建主体（用户优先）。
7. **成本**：辩论每作业可选（默认关）；消耗 = 主体数 × 分析员 + 裁判员；受 D-019 每作业上限约束；A2 常驻作业默认不跑辩论；tier 候选。
8. **运行形态**：多会话由 Backend `agent/` 会话池并行驱动（每主体一会话）；会话间不共享可写产物，经引擎合并；DuckDB 单写者不变。
9. **路线图**：Phase 2D；v1 非目标。协议包的导入 / 分享为商业化候选（`docs/agent/candidates.md`）。

## 取舍理由

- **主体与角色正交**：不改 D-019 的角色表与权限模型，只加一个参数；"多头分析员"与"空头分析员"是同一角色文件、不同主体。
- **作业树由引擎建**：并行需要稳定宿主（版本、介入、预算按子作业隔离），agent 提案、引擎创建，与"编排在代码里"一致。
- **crux 而非"更多反证"**：分歧地图把验证需求从"再采什么"磨尖为"什么事实能裁决"，直接接入 call 与裁决。
- **红队默认关、不是介入**：它是 agent 的产物，不能冒充人的介入进入协议蒸馏。
- **默认关 + 每作业可选**：3–5× 的分析成本只在用户要的时候花。
