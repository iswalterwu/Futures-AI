# D-025：开发工作区收敛与临时分支生命周期

- 日期：2026-10-30
- 状态：接受（Walter 本次要求整合衍生修改、删除衍生目录，以后不保留这么多 branch）
- 范围：本仓库开发协作，不改变产品运行时、需求或验收 Gate。

## 背景

`D:/2030` 累积了 30 个额外的 Futures-AI Git worktree，本地共 63 个分支。多数是历史规划、审核和引用快照，并不是需要长期并行开发的功能。另有独立项目，不能按名称相似或位置相邻删除。

## 决策

1. 默认只保留工作目录 `D:/2030/Futures-AI`，串行工作；常驻本地分支为 `main`（已验收主线）和 `workbench`（统一在研内容）。目录整合不等于功能完成或获准 merge main。
2. 审核仍须新开独立会话、固定提交、与实施隔离。需要文件系统隔离时，在系统 Temp 使用临时快照或 worktree，不在 `D:/2030` 新增长期衍生目录。
3. 只有确需并行写入时才创建临时 worktree / 分支，并遵守 AGENTS 的所有权和串行集成规则；任务结束先保存有效修改和审核证据，再移除临时 worktree / 分支，不留下一轮接着堆积。
4. 删除前盘点 tracked / untracked / ignored 文件及 detached HEAD；未整合的历史记录先保存为可独立恢复并校验的 Git bundle。`node_modules`、缓存和可重建测试产物不作为唯一工作成果保留。
5. 不以此次整理代替 feature Gate 1 / Gate 2，不代勾 checklist，不提前签收 H-x，不删除其他项目或擅自删除远端分支 / Draft PR。

## 取舍

不再为每次规划、每轮审核或每个批次长期保留一个分支与目录。保留必要的并行隔离能力，但临时资源必须回收；尚未最终验收的代码可放在统一工作分支，不能为减少分支而塞入 `main`。
