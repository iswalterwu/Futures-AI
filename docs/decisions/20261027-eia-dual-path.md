# D-014 EIA 取数双路径（API key 优先、免凭证回退）与用户档案归属

- 日期：2026-10-27
- 状态：accepted
- 相关：D-013（内置库存收敛）；data-layer v23；settings feature

## 背景

1. **agent workflow 需要 API**：后续 pi agent 经 MCP 取数，API 路径可按序列精确、实时取数，是 agent 的默认数据通道。故 API key 是**首选**路径，不能只做免凭证。
2. **注册无法全自动**：EIA 注册表单（`www.eia.gov/opendata/register.php`）可程序提交且无验证码，但 key **仅通过邮件发送**、页面不返回；TOS 勾选属用户的法律同意。程序替代提交/代勾条款不合适；接入用户邮箱（IMAP）会引入高敏感凭据与合规风险。
3. **免凭证路径确实存在且实测可用**：`https://www.eia.gov/dnav/pet/hist_xls/<SERIES>w.xls`（例：`WDISTUS1w.xls` → 200，2302 行历史，最新 2026-10-16 = 104286 千桶），无需 key、官方公开下载页；`api.eia.gov/bulk/PET.zip`（55.9 MB，含 `PET.WDISTUS1.W`）可作全量回填。二者与 API 同一 series code、同一单位。
4. **用户信息无处存放**：注册需要姓名/邮箱/组织类型，程序当前没有用户档案；每次都要手工输入不可接受。

## 备选方案

- **A+B（采纳）**：有 key 走 API；无 key 自动回退免凭证直链；档案在首次启动时收集并作为注册预填来源
- 仅免凭证：实现最简，但 agent workflow 失去 API 通道（拒）
- 仅 API key：无 key 用户完全不可用（拒）
- 程序代提交注册 + IMAP 自动收信：自动化最高，但需邮箱凭据、企业邮箱常禁 IMAP、代用户同意条款（拒）

## 结论

1. **EIA 取数双路径**：配置了用户 key → 官方 API；未配置 key → **自动回退**官方免凭证历史数据下载。两路径同口径（同 series code、同单位），可对账；回退不静默——状态与来源对用户可见。
   - 「未配置」与「配置了但读不出来」区分处理：前者回退，后者报错（凭证故障不能静默降级）。
2. **用户档案**在应用首次启动时收集：姓名、邮箱、组织类型是**数据源注册所需**字段，但档案本身**不是必填项**（可留空、可稍后填写，2026-10-27 Walter 批准时的调整）；仅在开通需要凭证的数据源时要求齐全。用途说明、接收通知为可选。档案**仅存本机、不上传**，用户可查看/修改/清除。
3. **EIA 开通为引导式**：程序用档案预填 → 用户在浏览器自行核对并提交（条款由用户勾选）→ 提示查收邮件 → 用户粘贴 key → 程序加密保存并**立即真实请求验证**，失败给出可操作提示。程序不代提交表单、不接邮箱。**验证通过才保存**（失败不落盘；凭证存在但读不出来时取数报错、不回退，与 data-layer D-014 第 1 条一致）。
4. 档案与开通向导归 **settings feature**；data-layer 只负责"双路径取数 + 凭证加密存储"。

## 取舍理由

- agent 优先与可用性兼顾：有 key 的用户与 agent 得到权威实时数据；没有 key 的用户仍能开箱可用
- 合规最小化：条款由用户本人同意，不碰邮箱凭据
- 隐私最小化：档案只留本机；程序不收集注册以外的信息
- 回退可见：避免"看起来有数据、其实是另一条路径/另一时点"的静默误解
