# D-013 data-layer 内置库存数据源收敛到交易所仓单口径

- 日期：2026-10-27
- 状态：accepted
- 取代：无（在 D-012 的 v1 范围基础上收窄 R-007 的内置数据源清单）

## 背景

v22 的内置数据源包含"东财库存日报"（FU/BU/LU/PG，measure=stock）。发布管线在线冒烟（2026-10-27，真实网络）实测结果：

| 观察项 | 结果 |
|---|---|
| 东财 `ON_WARRANT_NUM` 的含义 | 交易所**注册仓单**。2025-12-31 东财 FU=201390，与上期所页面同日值完全一致 |
| FU | 数据停在 2025-12-31（上游停更；akshare 1.20.1 同样） |
| BU | 仍在更新，但只统计**仓库**（2026-10-27 为 0），漏掉厂库（交易所合计 1560） |
| LU | 与交易所合计一致（11680） |
| PG | 仍在更新（单位口径待核） |
| 99 期货库存接口 | 已失效（内置 token 过期/改版） |
| 交易所仓单日报 | 五品种均可用至当日；此前因 akshare 品种名表缺「20号胶」整体崩溃，已由适配器自解析上期所页面修复 |

即：内置的第三方"库存"既与仓单是同一事实，又存在停更、漏厂库、单位待核等问题；真正的商业/社会库存（隆众、卓创等）是另一类数据，需付费源。

## 备选方案

- **A（采纳）** 内置数据源收敛到交易所仓单口径：R-007 的"仓单/库存"由交易所仓单日报承载（注册仓单即交易所口径的库存视图），移除内置第三方库存源
- B 保留东财、仅 FU 改用交易所仓单
- C 只删 FU 的 stock 序列，其余保持
- D 引入商业库存付费源（隆众/卓创/生意社等）作为内置源

## 结论

1. 内置数据源只保留**交易所仓单日报**作为库存视图（measure=receipt，SC/FU/LU/BU/PG 五品种）
2. 第三方商业库存（社会库存等）**v1 暂缓内置**——数据源口径复杂，待后续选定源并实测后再通过数据源机制接入；期间用户可用自带数据源接入。`measure=stock` 保留在封闭枚举中，供用户清单 / 本地文件使用
3. spec R-007 与 AC-007-1 措辞同步；plan 的内置清单删除 4 条 stock 序列与东财库存取数路径

## 取舍理由

- **单一权威口径**：同一事实不应有两个可能互相矛盾的内置数字；日报里的"库存"必须可信
- **可用性**：仓单日报五品种当日可用；东财源有停更品种、有漏厂库品种，会让使用者误判
- **诚实边界**：商业库存与注册仓单是两类数据，不能用一个冒充另一个；其数据源（多为付费/授权）需要单独选型与实测，故 v1 暂缓而非删掉需求
- B/C 保留了不可信数字（B 让 FU 的 stock 与 receipt 完全同值，C 把问题藏起来而非解决）
- D 依赖外部商务条件（账号/付费/授权），作为后续阶段推进：先选源、实测口径与覆盖面，再走数据源机制接入
